# 0.2.1 preparation notes

This source update prepares the five publishable packages at `0.2.1` and
aligns their workspace and peer references to `^0.2.1`. On 2026-10-07, registry
queries confirmed `latest: 0.2.0` for all five packages; neither npm nor local
or remote Git tags contained `0.2.1`. This preparation does not publish npm
artifacts, create a release tag or deploy the documentation site. Follow
[Publishing](PUBLISHING.md) for those separate release steps.

## Included changes

- The four elementary Score Analyze tools use the accepted chord, interval,
  explicit-scale and grouped-rhythm contracts in DEC-047–049. Chord score/live
  modes share the note/name separation; fixed readout fields retain their
  position as playback advances.
- Mixed-meter inspections accept one explicit beat-group list per numerator.
  Chord selections retain exact authored endpoints. Narrow wrapped bands hide
  their label stack while retaining the full current reading and semantic
  entry. Live note announcements and irrelevant attribute validation are fixed.
  Spaced group expressions such as `2 + 3` remain accepted, and rhythm tools
  ignore the unrelated `pitch-mode` attribute.
- The independent-loops demo reuses cached opening excerpts from the existing
  Arabesque No. 1 recording, with retry after a failed load. Cached excerpts
  own their short sample buffers instead of retaining the complete recording.
- Reviewed dependency updates include the exact entities license snapshot.
  A scoped PostCSS override removes the older nested selector parser; DEP-02
  tracks when that override can be removed.

## Compatibility review

Harmonic interval output now includes a note sustained beneath a later attack
in the same voice. Consumers comparing interval counts with `0.2.0` must review
this behavior. Explicit beat groups apply only to the numerator matching their
sum; other conventional meters retain their usual grouping. Irregular meters
still require an explicit matching grouping. See the
[Analyze API](../../apps/doc/webmusic/src/content/docs/score/api/analyze.mdx),
[component references](../design/ANALYZE-COMPONENTS.md) and
[review corrections](../log/2026-10-07-score-analysis-review-corrections.md).

## Validation and delivery

Validate the exact prepared commit with `npm ci`, `npm run check`,
`npm run docs:build`, `npm run pages:build`, `npm run audit:production`,
`npm run audit:dependencies` and `npm run check:external-install` before
delivery. A prior review's passing results do not verify new version metadata.
Inspect remote CI for the pushed commit separately. Current release work and
remaining device/browser acceptance belong to [STATUS](../STATUS.md).
