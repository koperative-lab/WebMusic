This continues the [twelve-finding follow-up](MODULAR-RELEASE-FOLLOWUP-FIXES.md)
on branch `modular-redesign`, based on `ef8664dbb68ece9dc8c1d328141989a0ae86f888`
plus the retained working-tree changes. The scope is two newly reproduced
reentrant lifecycle failures, DEP-02 development dependencies and DEV-05 public
media. Earlier audit results retain their original baselines.

The lifecycle fixes were cross-reviewed by separate reviewers. The final built
Kernel public entry passes all three controlled scheduling cases. The final
Audio and Kernel public entries pass all three native offline mixer cases,
without source aliases or browser errors; exact input hashes are retained.
The asset review
independently parses MIDI/MXL and decodes WAV/MP3 with FFmpeg. Both audio files
decode to 1,411,200 frames at 44.1 kHz stereo (32 seconds); PCM correlation is
0.9999067. Chromium independently confirms decode duration and bounded, nonzero
samples. These are digital measurements, not device listening or latency tests.

The original study's melody is traceable to the repository's MIT generator at
`b714a004a0f604ad6717704d237cee3409ad14d1`. This does not assign a license to the
removed resources or clear an earlier deployment. Their binary recovery backups
remain outside the repository and are excluded from retained release evidence.

## Dependency boundary

The scoped override is temporary until Expressive Code adopts the safe nested
major itself. Nested 7 retains the same public types and PostCSS 8 peer contract;
its Node 18 floor is below this repository's supported versions. No unrelated
dependency was upgraded. npm 11.9 reports workspace override entries as invalid
through `npm ls`, including the pre-existing tsup/esbuild override and a clean
minimal reproduction. Actual `npm ci`, resolved package inspection, audit and
CSS compatibility checks establish the installed candidate; `npm ls` is not
reported as a passing gate.

## Release boundary

This work does not publish packages, create a tag or deploy the site. A reviewed
release commit still needs its Node 22/24 CI, authenticated registry delivery and
fresh registry consumer verification. Physical-device, wider browser and
background-scheduling acceptance retain the limits in STATUS and previous
records. A successful local check is evidence for this working tree only.
