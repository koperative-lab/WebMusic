## Confirmed corrections

Paths below are relative to this checkout. Source references describe the resulting source; exact lines can move during root's integration.

1. **MIDI metronome units.** `formats/midi.ts:466` now encodes quarter BPM (`bpm * unit`). An independently decoded FF 51 tempo field for half-note=60 was **1,000,000 µs/quarter**; the correct value is **500,000**. The regression reads the three raw tempo bytes rather than using our MIDI importer as its oracle.
2. **MIDI sounding events.** `formats/midi.ts:481–512` now realizes the same Score-domain tie/transposition semantics as playback, through existing Core helpers: contiguous ties become one attack, written D4 with chromatic −2 exports C4, and a tied event extends to its furthest performed/notated endpoint. Previously the example exported two D4 attacks of 480 ticks each; it now exports one C4 attack of 960 ticks. Source notation remains unchanged. Untied repeated concert-pitch attacks remain separate. Rests and un-realized grace notes do not create inferred MIDI attacks.
3. **MIDI field bounds.** The writer rejects PPQ outside integer 1…32767 (`midi.ts:457`) and sounding pitches outside integer 0…127 (`midi.ts:504`). Invalid values previously reached byte serialization. Tests exercise zero, negative, fractional, nonfinite and high-bit PPQ plus pitches below/above the MIDI data range; PPQ 32767 is a positive control. This does not assert exhaustive validation of every possible malformed Score field.
4. **Unsupported MIDI time models.** `midi.ts:167–176` explicitly rejects SMPTE division and type-2 independent sequences, rather than treating both as a shared quarter-note timeline. A hand-authored −25 fps × 40 ticks/frame SMF encodes a 1,000-tick/one-second note; previously it silently entered the 480-PPQ fallback. Implementing a correct SMPTE/independent-sequence conversion is not claimed by this change.
5. **MusicXML document time for overlapping notes.** `formats/musicxml/serializer.ts:143–166` now emits backup or forward moves when the next note's actual onset differs from the document cursor. A stale/orphan chord flag cannot override onset, and chord members cannot outlast their anchor. A separate, small MusicXML cursor interpreter expected onsets `[0, 0, 720]` divisions but observed `[0, 960, 1440]`; the output now preserves the expectation without requiring caller-authored chord metadata.
6. **MusicXML schema child order.** `serializer.ts:352` moves visual `<notations>` after voice/type/staff, while performance `<tie>` stays before them. Existing output put notations before voice, contrary to the MusicXML 4.0 note sequence. The test checks these semantically required relative positions; no full-document XSD compliance claim follows from it. Positive-safe-integer divisions are also validated before serialization.
7. **ABC omitted unit length.** `formats/abc.ts:114–131` follows the numeric meter when L is absent: 1/8 at meters ≥3/4, otherwise 1/16. Previously every omitted L became 1/4. Independent tests cover 4/4, 3/4 and 2/4, with explicit L:1/4 retained as the compatibility control. Public documentation explicitly explains this behavioral correction.
8. **ABC accidental state and barline lexing.** `abc.ts:157–196,387` carries explicit accidentals by pitch letter through the bar, clears them on barlines/natural replacement, and does not mistake `[|` for an opaque chord opener. The serializer writes explicit naturals so external readers do not interpret `^F F` as two sharps when the Score contains F-sharp then F-natural. Tests include same-letter propagation, cross-octave default propagation, natural cancellation and a thick barline. Unsupported key/propagation directives remain diagnosed/ignored rather than becoming a new full ABC dialect implementation.
9. **MXL path collision.** `formats/mxl.ts:201–204` rejects empty `scorePath` and `META-INF/container.xml`, which could produce an undiscoverable archive or overwrite its manifest. A nested `scores/main.musicxml` positive case still loads correctly. No new archive extraction destination or filesystem operation is introduced.
10. **Invalid JavaScript format hint.** `load.ts:150` rejects unsupported hints such as `json`; the prior exhaustive-at-TypeScript-level switch could fulfill `loadScoreDetailed` with undefined for such runtime input. The worker protocol already rejected this shape; the direct loader now fails explicitly too. JSON persistence remains Core's model API, not a new file format.
11. **Malformed worker diagnostics.** `worker-client.ts:509` rejects `location:null` as a terminal protocol failure. Previously the message listener threw a TypeError while inspecting `partId`, leaving the parse promise pending. The regression asserts no listener throw, request rejection and exactly one Worker termination.
12. **Factory disposal reentry and late rejected tasks.** `worker-client.ts:183–210,320` retains a factory-returned Worker as a candidate until client state is rechecked, terminates it if the factory disposed the client, and does not send parse/cancel work to it. `cancellation.ts:95–98` observes a started task's rejection even when cancellation has already won. The baseline produced a late cancellation message, leaked the returned Worker and reported an unhandled rejection; the new test rejects cleanly, posts nothing and terminates once.

The first 18 format assertions failed against the baseline after correcting an initial test-fixture mistake (`Rational.fromFloat` does not exist). Those corrected-fixture failures are the actual before evidence, not the fixture error. Both new worker cases also failed before their source fixes. Additional bounds, positive controls, thick-barline and unsupported-format cases were then added; the final new files contain **25 format tests + 2 worker tests**.

## Design decisions retained

Keep the stateless I/O root and narrower formats/load modules. Keep Worker client/protocol/runtime separate because ownership, message lifetime and import side effects differ. Keep MusicXML's ordered-tree/walker/parser/serializer separation: it allows document cursor and Score construction rules to be reviewed independently. No additional generic component, frontend layer or Core model fork is needed.

Serialization is a projection with stated loss, not a lossless save of the original interchange document. MIDI realizes sounding events; MusicXML retains supported notation; ABC emits a deliberately restricted stream. A `Detailed` result records recognized normalization families and does not certify that all unsupported source constructs were detected. Public documentation now states these differences rather than presenting every format as interchangeable.

## Remaining limits

No claim of complete MusicXML/ABC/SMF/ZIP conformance, preservation of all authored metadata, or bounded real-time latency. MusicXML still takes the first part's grid/tempo, cannot represent mid-measure structure and changing part transposition faithfully, and does not retain all tuplets/lyrics/articulation/engraving details. MIDI control/pitch-bend/key metadata is explicitly lost; same-pitch hardware voice behavior, program changes while notes are held, extreme event-density/tempo counts, very long deltas and all header-field boundary combinations were not exhaustively exercised. Percussion display-pitch/instrument mappings are not inferred. ABC still omits unsupported expressive/polyphonic constructs and reports only known loss families.

Worker tests use controlled Worker-like objects and structured cloning; actual browser worker construction, bundler URLs, message scheduling and synchronous parser preemption remain separate acceptance work. Resource caps limit allocation families but do not constitute a malformed-input security audit or a maximum-duration guarantee. Source/tests/reference are frozen for root's integrated verification.
