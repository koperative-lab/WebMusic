## Findings and repairs

1. **Outer styling was incomplete for Harmony, Pitch and Workbench.** Their roots/frame now use the existing `componentSurfaceDeclarations` contract: `--wm-<family>-surface-{background,border,padding,radius}` → `--wm-component-*` → prior presenter/semantic fallbacks. Harmony/Pitch keep transparent, zero-border/padding defaults. Full Workbench preserves its existing harmony border/padding; bare Workbench still defaults to zero but accepts explicit surface values. Workbench now exposes built-in `part="frame"` plus `parts.frame`; its root remains the unpainted query container.
2. **Compound surfaces could repeat border and alpha paint.** Harmony's four mounts and Pitch's three mounts accept additive `surface?: 'default' | 'none'`. `none` suppresses only outer background/border/padding/radius using a shared internal declaration record, on either stylesheet path; data marks, controls and palette remain active. Score Analyze uses it for nested lane/nameplate; Score Waterfall uses it for nested keyboard (other owners). The flow viewport and note grid no longer repeat root background paint. Minimap's inner viewport no longer repeats an inherited global surface; its explicit inner `--wm-minimap-background` remains supported.
3. **Selected text was incorrectly derived from background.** Harmony previously used `--wm-analysis-background` / `--webscore-analyze-bg` for selected foreground; LFO buttons used `--wm-surface`. A transparent background made text transparent. Corrected selected text uses explicit `--cp-accent-foreground`, `--wm-harmony-on-accent`, `--wm-accent-foreground` (or presenter-specific LFO foreground), preserving their intended precedence and literal defaults. Parent explicitly accepted removal of the accidental background-as-text compatibility reuse.
4. **Standalone helper reads skipped public semantics.** `harmonyValues` direct reads now reach public harmony/analysis/legacy/shared paint tokens when no private ancestor token record is installed. Harmony, Pitch and Workbench reuse these reads. Existing token-record cp and explicit presenter precedence remains. Muted foregrounds across controls/readouts now fall through `--wm-foreground-muted` to `--wm-foreground`, preserving their literal defaults. Transport time text also reaches shared foreground before its internal fallback.
5. **Note/Pitch paints had gaps.** Note uses shared surface/inverse/accent/accent-foreground/foreground fallbacks, including black-key label and border hooks. Both white and black active piano labels now use `--wm-note-label-active` → `--wm-accent-foreground`, matching grid/chord selected-label semantics. Pitch keys retain their existing `--wm-note-*` hooks and gain shared surface, inverse, border, foreground and control-radius fallbacks. Staff and fret geometry paints now have public `--wm-pitch-staff-line` and `--wm-pitch-fret-{neck,wire,nut,string,inlay}` hooks; old private overrides remain before them for compatibility. Musical role palettes and per-pitch colours remain independently configurable.
6. **Other palette holes.** Recorder accent/text/track now reach shared accent/accent-foreground/muted-surface; meter track reaches shared muted surface. Envelope/EQ/LFO inverse viewport paint reaches shared surface after explicit inverse token; envelope/EQ inverse ink reaches shared foreground after explicit inverse foreground. LFO primary/selected fills reach accent before foreground. Harmony/analysis chips now accept shared control radius without moving their zero-radius default.
7. **Per-band data could hide an application fill override.** `--wm-harmony-flow-tone` now precedes the per-band internal tone value, so changing the public token overrides coloured data bands and clearing it restores their palette.
8. **References overstated universality and advertised internal properties.** All 21 owning leaves link the shared surface/palette contract. Index/README distinguish frame shorthand from inner edge colour, outer transparency from independent musical/inverse/overlay paint, inline support from omitted stylesheet installation, and compound surface ownership. Harmony/Pitch/Workbench describe new options/parts/public paints; old `--wui-*` tables are explicitly compatibility/state material, not a second public theme system.

Literal unthemed defaults were retained except the deliberate active piano label correction and the removal of background-derived selected text. Parent coordinates a final black-key compatibility refinement: use `--wm-note-key-alt-border` → `--wm-border` → `#000`, omitting a captured `--wm-note-border` fallback, so the Score preset's default white-key edge does not change black-key defaults. The owning note page already records this final intended chain.

## Limits

This agent's evidence is source/DOM and authored CSS token-chain coverage. jsdom does not resolve inherited custom properties, paint alpha, evaluate container queries, rasterize canvas or establish visual contrast/accessibility. Real browser default-vs-custom themes, transparent surfaces, both narrow/wide layouts, parts cascade and runtime changes are parent-owned acceptance. No audible/device/timing conclusions follow from these styling tests. With `stylesheet:false`, only Analysis (always inline), Harmony, Pitch, Workbench and Transport supply their documented inline skin; other mounts still require caller-owned exported styles or replacement CSS. Focus and pseudo/container rules still need actual CSS even on inline-capable mounts.
