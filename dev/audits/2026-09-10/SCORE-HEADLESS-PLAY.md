## Authoritative references

- [Web Audio API 1.0, W3C Recommendation, 17 June 2021](https://www.w3.org/TR/2021/REC-webaudio-20210617/): `BaseAudioContext.currentTime`, suspend/resume, scheduled source timing, Biquad response semantics and [WaveShaperNode interpolation](https://www.w3.org/TR/2021/REC-webaudio-20210617/#WaveShaperNode). The curve regression uses the specification's independent mapping `v = (N−1)(x+1)/2`, linear interpolation between neighboring curve values, and endpoint clamping.
- [Web MIDI API, published specification](https://www.w3.org/TR/webmidi/) (consulted 2026-09-10): `MIDIOutput.send` timestamps are DOMHighResTimeStamp milliseconds, past/zero timestamps are immediate, and disconnected outputs can reject sends. This implementation intentionally sends at the audio-clock-controlled callback; it does not pass AudioContext seconds as MIDI timestamps or clear all messages on a borrowed output. The reference is the published URL consulted, not a claimed pinned edition.

## Remaining verification boundary

The changes remove independently reproduced mathematical, identity and lifecycle faults. They do not establish sample-accurate cross-engine synchronization. AudioContext sharing, timer wakeups, MIDI delivery and worklet messaging have distinct clocks/latencies; accepted shared-clock injection remains a separately tracked implementation gap.

MIDI software occurrences now release exactly once, but MIDI 1.0 same-pitch overlapping voices have device-dependent audible behavior. Real browser suspension/background throttling, audio device closure, worklet startup, actual sound-bank playback, audible phase/DC behavior and external WAV decoding were not validated here. Numeric fuzzing, every Sound-layer failure and every Rack graph replacement combination were not exhaustive. No unproven suspicion has been promoted to a defect or silently added to scope.
