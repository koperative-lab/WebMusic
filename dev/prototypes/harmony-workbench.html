Harmony Workbench

页面一打开就在播。now 线钉在视口 33% 处不动，和弦带、级数、动机从右往左流过它—— 你看得见下一个和弦正在逼近，这就是这次转向的全部理由（设计 D2）。 六个 tab 各自在内部变活（D1）；四个坞位（键盘 / 谱表 / 指板 / 名牌）吃同一次 projectSounding()，所以同一个音在四个面上永远是同一个颜色、同一个角色。

假的：和弦命名 / 拼写 / 把位是内联的最小替身表（实现里是 score 的四个 core 模块）； 没有 Score 解析、没有 worker、没有增量 session；「播放器」是一个 50ms 的 setInterval 假事件源；样式是一个 <style> 块，不是 token-as-data 的双路径； 没有 destroy() / claimHost / SSR；谱号用 Unicode 字形（实现里由 score 传入）。
真的：运动模型（固定 now 线 + 单节点 transform + 三区穿越 + 排空）、 版面与容器查询三档、harmony-style.ts 的真实色盘与七个 motion token、 「一次投影喂四个坞位」的纪律、三层时钟（20Hz 事件 → headless 预测 → 每帧一次读数）、 data-start-quarters 跨度契约与跑在它上面的 createAnalysisPlayhead 复刻、 以及减动效档下逐像素相同的布局。 和声分析（调判定 / 动机 / 平行五度）也是当场算的，不是写死的结论。

这一屏在验证什么

now 线不动，材料动。整条传送带每帧只有一个节点被写样式（__reel 的 transform），band 的 left/width 是它自己字段的纯函数、 与 now 无关——因为 createAnalysisPlayhead 会整条覆写 band 的 style.cssText，任何逐帧写在 band 上的东西都会在它抵达 now 线的那一刻被抹掉。

一个音只有一套读数。点右栏任意一个备选命名，键盘、谱表、指板、名牌的角色配色整体重算—— 四个坞位吃的是同一次 projectSounding()。指板画的是能按下去的把位， 所以它按音级与角色与其余三个一致，不按八度。

减动效不是另一个视图。把 Motion 拨到 Reduced：帧循环根本不开， 位置改由 20Hz 的域事件一格一格步进，而布局逐像素相同——你依然看得见下一个和弦在逼近。 预期是布局的属性，不是补间的属性。

三层时钟。把 Clock 拨到 Raw 20Hz：预测层被摘掉，传送带立刻变成「停两帧、第三帧跳 6px」。 这就是加了滚动之后「静态」长什么样。

停靠不是空白。Phase → Idle：走带停了，但整首曲子已经画完、可以拖、可以按 ←/→、[/] 走和弦边界，线下读到什么四个坞位就报什么。

建它的时候，设计被推翻的地方

band 的底色band 自己的 background 必须留空。harmonyParts.activeSpan 写的是内联 background: var(--wui-harmony-track)，内联赢过任何选择器——所以直接把 tone 填在 band 上，抵达 now 线的那一个（唯一重要的那一个）会变成一块中性灰。填充必须住在子节点 __band-fill 里。设计 §3.6.4 只写了「lane 不许逐帧写 band 的内联样式」，没写反方向
容器查询容器查询永远不能给自己的容器写样式。container-type 必须落在 .wui-harmony 上，而 grid-template-areas 落在 .wui-workbench 上。两者同节点时三档断点静默失效——原型第一版就是这样，440px 下 rail 没有下沉
帧循环停了谁来推标签页被藏起来 / 离屏 / 降频时，lane 仍然必须被域事件推进，否则坞位在 20Hz 更新而传送带冻住——同一屏上两个读数互相打架。设计 §3.0.2 只说了「hidden 退出循环」，没说这时谁负责位置
2 列谱表设计 §5.0 让 voice-leading 的 staff 吃 2 列并钉 activeColumn = 1。那会让谱表与其余三个坞位对不上：播放头在边界之前时，第 1 列不是正在响的那一组。activeColumn 必须跟着 now 走，另一列做 past / next 的 ghost
多轨的钉住读数FlowLaneState 需要一个 pinTrack：多轨时「钉住的大字读哪一条」推不出来——roman 必须钉级数，不能钉最上面那条调带
轨高与视口高轨高一旦不齐（ribbon 8px、刻痕轨 2×），视口高度就不能由 data-rows × lane-height 得到，只能在内容变化时按累计偏移写一次。FlowTrack 因此需要 heightScale
细带的填充4–8px 的调带吃不起 ahead 的 32% 填充：细长的东西需要饱和度。三区的百分比对 48px 的 band 成立，对 ribbon 不成立
七个 motion token设计 §2.5.2 列的七条里，harmony-style.ts 今天只有两条。另外五条（-flow / -pop / -release / -column / -turn）本原型全部用到了，确实都需要

原型 vs 真实实现

和弦命名原型：15 段的查找表 + 真实的角色算术；实现：@tonaljs/chord-detect 的全部候选 + spellChord()
调判定原型：当场算的 Krumhansl 相关（时值加权直方图）；实现：detectKey() / createLiveKeyTracker()
动机原型：当场跑的重复音程搜索 + 贪心去重叠；实现：findMotifs(score, {length, minOccurrences})
声部问题原型：当场跑的平行五 / 八度 + 大跳检测；实现：voiceLeading(score)
时钟原型：50ms 假 timeupdate + coast 预测；实现：score-player 的真事件 + headless/transport-clock.ts
帧循环原型：一个 rAF、按订阅者计数自停、离屏退出；实现：packages/ui/src/internal/frame.ts
跨度契约原型：data-start-quarters + data-webscore-idle-style 与 playhead 复刻俱在；实现：internal/spans.ts + 白名单里的 internal/playhead.ts
