# Security policy

## Supported versions

WebMusic is preparing its first public release. There is no promised security
maintenance window for a published version yet. Reports about the current
`main` source and any publicly available WebMusic package are welcome; include
the exact affected version or commit. Release availability must be checked in
the registry and repository releases, not inferred from package manifests.

## Report a vulnerability privately

If GitHub private vulnerability reporting is enabled for this repository, use
[Report a vulnerability](https://github.com/koperative-lab/WebMusic/security/advisories/new).
This policy does not assert that the repository setting is enabled.

If that form is unavailable, use a private contact channel published on the
[maintaining organization's profile](https://github.com/koperative-lab).
If no private channel is listed, open an issue asking the maintainers to
provide one or enable private reporting. Do not include vulnerability details,
exploits, secrets or sensitive attachments in that public request.

Include the affected package and entry point, version or commit, environment,
steps to reproduce, expected impact and a minimal proof of concept where
possible. Use synthetic data and remove credentials. Report suspected package
tampering or compromised release artifacts with their registry URL and
integrity information.

Maintainers will assess the report and coordinate remediation and disclosure
through the private channel. No response-time or remediation-time guarantee is
offered. Please allow time for assessment before publishing exploit details.
Ordinary bugs and feature requests belong in the
[issue tracker](https://github.com/koperative-lab/WebMusic/issues).
