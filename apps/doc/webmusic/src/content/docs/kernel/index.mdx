`@webmusic/kernel` is the foundation of the WebMusic ecosystem: the contracts
and pure runtime logic that both families build on. It is deliberately
**zero-domain** — it knows nothing about scores or clips. No `Note`, no
`Score`, no `AudioClip`, no `BeatGrid`. What lives here is only what both
families genuinely share: event emitters, custom-element plumbing, worker
plumbing, AudioContext construction, playback and effect contracts, and
transport math.

## The five packages

WebMusic ships five lock-stepped packages. The kernel sits at the bottom of
the dependency graph and publishes first:

| Package | Role | Peer dependencies |
| --- | --- | --- |
| `@webmusic/kernel` | Zero-domain runtime contracts and pure logic | — |
| [`@webmusic/ui`](/uikit/) | Dependency-free DOM presenters and styling hooks | — |
| [`@webmusic/score`](/score/) | Symbolic music — MIDI, MusicXML, MXL, ABC | kernel, ui |
| [`@webmusic/audio`](/audio/) | Digital audio — decoding, playback, MIR analysis | kernel, ui |
| [`@webmusic/bridge`](/bridge/) | Code that must know both domains | kernel, score, audio |

Score and Audio never depend on each other. Anything that needs both —
synchronized playback, score-to-clip rendering, transcription assembly —
lives only in the [bridge](/bridge/).

## One shared instance

Every consumer declares the kernel (and ui) as a **required peer**, so npm
installs exactly one copy and version skew fails loudly at install time
instead of silently duplicating the kernel. At runtime the whole ecosystem
shares **one** kernel instance. Contracts keep a single identity: a
`PlayerLike` implemented by a score player is the same interface a transport
UI checks against, and `instanceof WebMusicElement` works across packages.
(npm 7+ installs non-optional peers automatically — `npm install
@webmusic/score` still brings everything it needs.)

## The admission rule

Code qualifies for the kernel only if:

1. two drifting copies of it already exist in the families, or
2. it is a contract both domains must implement.

Everything else deliberately stays per-family. The extraction ledger — what
moved here, from where, and what stayed behind — lives in the repository's
`platform/README.md`.

## For third parties

Implementing a WebMusic-compatible player, effect, or timeline mapping means
depending on `@webmusic/kernel` directly and implementing its structural
contracts — no domain package required. Element authors can subclass
`WebMusicElement` for connected-lifetime cleanup with SSR-safe imports.

See the [API reference](/kernel/api/) for the nine entries and their
contracts.
