`@webmusic/score/view` turns `Score` objects into layout data and visual renderings, and owns [document editing](#document-editing). Its three visual Web Components are `<score-view>` for score-position views, `<score-pitch-view>` for sounding pitches, and `<score-sheet-view>` for optional full engraving. An editable document is a [`ScoreEditor`](/score/headless/view/score-editor/) that your application owns and lends to views and players.

Playback lives in [`@webmusic/score/play`](/score/api/play/). Views borrow player data or events according to their owning contracts; the static thumbnail renderer is a passive whole-score preview. Imperative renderers expose `redraw` for application-driven highlighting.

## Install

`npm install @webmusic/score` — use an available published version or the local workspace; [Install](/score/#install) has the full setup.

The root model and this capability ship in that one package. The browser staff
renderer includes its VexFlow dependency; it needs no separate installation.
Optional integration:

```txt
@webmusic/score/io     sibling capability used by the Web Component to load a `src` file
opensheetmusicdisplay  required only for the separate OSMD page-engraving workflow
```

The view capability has four entry points — the [package subpath table](/score/api/#package-subpaths) lists them with every other `@webmusic/score` entry:

The `@webmusic/score/view` root is the **stateless API** (serializable layout data, the note-sequence view model and the pure edit operations). `/headless` provides [score-window, map-navigation, held-pitch, editing and editor models](/score/headless/#view): they own reusable view behavior and optional playback subscriptions without creating UI or choosing visual styles. Imperative SVG/Canvas/OSMD adapters live explicitly on `/render`, while the custom elements live on `/element`.

The browser renderer implementation is also separated by responsibility: shared sizing/lifecycle, SVG virtualization, piano-roll, waterfall, staff, and the public factory each live in their own internal module. These internals are not package subpaths; consumers should use `/render`.

## Web Components

`<score-view>`, `<score-pitch-view>` and `<score-sheet-view>` live on `@webmusic/score/view/element`. Their owning pages under [Web Components › View](/score/element/#view) document each tag’s types, attributes, events, player binding and styling. This page owns the code-facing APIs they compose.

The code-only APIs below let you maintain view state or build your own renderer; the explicit `/render` adapters draw into browser elements. The examples assume a `score` built with `@webmusic/score`.

## Prepare a score

Score layout APIs work from a `Score`; current-pitch projections below instead accept MIDI values. The live view demos use an opening excerpt of the same Arabesque No. 1 MXL file used by the Score view elements.

```ts
import {loadScoreFromUrl} from '@webmusic/score/io';

const score = await loadScoreFromUrl('/mxl/Arabesque%20No.1.mxl');
```

## Create a code-only score view

`createScoreView` is a stateful domain component for application code. It
converts the score once, tracks playback state, recalculates active notes on a
seek, and computes the notes intersecting a requested time window. Its state is
immutable plain data, so it can drive React, native UI, WebGL, a terminal, or a
custom renderer without creating an element or applying a style.

```ts
import { createScoreView } from '@webmusic/score/view/headless';

const view = createScoreView(score, {
  type: 'piano-roll',
  viewport: { startTime: 0, endTime: 8 },
});

const unsubscribe = view.subscribe((state) => {
  drawMyOwnView(state.visibleNotes, state.activeNotes);
});

view.noteOn(60, 0);       // direct player-style control
view.seek(4);             // activeNotes is recomputed at 4 seconds
view.setViewport(4, 12);  // publishes a new immutable snapshot

unsubscribe();
view.dispose();
```

## Document editing

Editing is a View feature. This root exports the stateless parts: the
`applyScoreOperations` helper, exact position maps, the shared document port
contracts and `ScoreEditError`. The stateful
[`ScoreEditor`](/score/headless/view/score-editor/) on
`@webmusic/score/view/headless` adds one document owner, revision guards, local
history and interaction drafts, and `loadScoreEditor(url, options?)` there loads
a file into a new caller-owned editor. Elements borrow an editor only through
their `.editor` property. None of them creates a player, clock or visual
surface. [Score player](/score/headless/play/score-player/) and
the editable views borrow the same Core ports, which the
[`@webmusic/score` root](/score/api/) also exports.

### Atomic note operations

`applyScoreOperations(score, operations)` returns a candidate `score`, a
defensive immutable snapshot of `operations`, and `affectedNoteIds`: the notes
the batch inserted, removed or changed relative to the input, in first-touched
order. A note inserted and deleted, or changed and restored, within the batch
is not listed; a net-zero batch returns the input Score and no IDs. Operations
run in order; invalid input throws `ScoreEditError` without modifying the source.
The helper has no document identity, revision, history or subscriptions. Use
`ScoreEditor.execute` when the operation must also commit to an owned document.

Every operation has the following exact fields. IDs refer to authored notes,
not repeat-expanded playback occurrences. Insertions supply their own stable IDs.

| `type` | Fields | Meaning |
|---|---|---|
| `insert-notes` | `notes: ScoreNoteInput[]` | Add notes to existing parts. Each input has `id`, `partId`, written `pitch: {step, alter, octave}`, `onsetQuarters`, `durationQuarters`, `voice`, and optional `velocity`. |
| `delete-notes` | `noteIds` | Remove the named notes. Tied, tuplet and grace notes reject as `unsupported-structure` even when the whole chain or group is named; deleting only part of an authored slur pair or beam group also rejects. |
| `move-notes` | `noteIds`, `deltaQuarters` | Shift written onset by exact rational quarters, retaining Duration notation. |
| `resize-notes` | `noteIds`, `durationQuarters` | Set a positive exact quarter duration for simple notes. |
| `transpose-notes` | `noteIds`, `semitones` | Transpose written pitch by an integer number of semitones, respelled as described below. |
| `set-velocity` | `noteIds`, `velocity` | Set integer velocity 1–127; rests and tie continuations reject. `null` clears the authored override. |
| `quantize-notes` | `noteIds`, optional `grid`, `origin`, `target` | Snap onset, duration, or both to a rational grid. Defaults: grid `[1,4]`, origin `[0,1]`, target `'onset'`; ties round forward. |
| `enter-notation` | `entry: ScoreNotationEntry` | Enter a spelled note or rest in one existing measure and one voice/staff, replacing fully covered events and filling remaining gaps with written rests. |

`ScoreQuarterValue` is a reduced safe-integer `[numerator, denominator]` pair
with positive denominator. Onsets cannot become negative and ordinary-note
durations must remain positive. Invalid/unknown IDs, duplicate insertion IDs,
unsupported operation fields or structures reject the whole batch. Commands do
not repair partial ties, tuplets or grace notation. Only `enter-notation` fills
the selected measure/voice/staff with written rests; ordinary piano-roll
operations retain their event-editing behavior.
Insertion, transposition and notation entry require a written MIDI pitch of
0–127 and, after adding the Part transposition (`chromatic + 12 × octaveChange`),
the sounding pitch 0–127 that playback and MIDI export use. Transposition
rejects tied, rest and unpitched notes. A numeric `set-velocity` rejects rests
and tie continuations, the later notes of a tie chain. Playback and MIDI export
sound each tie chain once with its first note's velocity, so set that note
instead. `null` may clear any stored override. Quantization origin affects
onset only; duration quantization uses origin zero, and a duration rounded to
zero rejects.

Transposition by a multiple of 12 semitones keeps the written step and
accidental and changes only the octave: `Bb4` becomes `Bb5`, and `E#4` becomes
`E#5`. Other intervals spell the resulting pitch by the original accidental
direction. A note spelled with a flat keeps flats (`Bb4` + 3 is `Db5`); a
natural or sharp note uses sharps (`D4` + 1 is `D#4`); white keys are naturals
(`Eb4` + 1 is `E4`). These results never contain double accidentals and do not
consult the key signature.

Resize, duration quantization and insertion store a written Duration for the
exact quarter length. A length spelled by a whole through sixty-fourth base
with zero to two dots uses that spelling: `[3,4]` is a dotted eighth and `[7,8]`
a double-dotted eighth. Any other length, such as `[5,4]` or `[1,3]`, becomes
its own base with no dots and has no single-note staff spelling. A move keeps
the existing Duration.

Deletion keeps authored slurs and beams matched. A slur's `start` and `stop`
endpoints pair by voice and slur number; a level-one beam group runs from
`begin` through `end` in one voice and staff, with chord members sharing their
onset. Delete such a pair or group entirely, or not at all; a partial deletion
fails with `unsupported-structure`. Unmarked notes inside a slur can be deleted
individually, and already unmatched marks are not protected.

An effective move, resize or quantize makes written time authoritative for each
changed note: it removes absolute `performed` timing and retains the prior
effective velocity in `velocityOverride`. Sounding duration follows the new
quarter endpoints through the TimeMap, including interior tempo changes.
Pitch-only, velocity-only and no-op timing operations preserve performed timing;
untouched notes retain imported microtiming. Effective velocity is
`velocityOverride ?? performed?.velocity ?? 80`.

Quantization compares written time only. A note whose written onset and
duration already lie on the grid is unchanged and keeps its `performed` timing.
For example, [Score Recorder](/score/element/play/score-recorder/) output
with a nonzero `quantize` already has grid-aligned written time. Quantizing it
to that grid is a no-op, and playback and MIDI export continue to use its exact
performed timing.

This standalone example creates an explicit input and computes a candidate:

```ts
import {Duration, NoteId, PartId, Pitch, Rational, ScoreBuilder, VoiceId} from '@webmusic/score';
import {applyScoreOperations} from '@webmusic/score/view';

const partId = PartId('piano');
const noteId = NoteId('opening-note');
const builder = new ScoreBuilder();
builder.addPart({id: partId, name: 'Piano', midiProgram: 0, staves: 1});
builder.addNote(partId, {
  id: noteId, pitch: Pitch.parse('C4'), onsetQuarters: Rational.ZERO,
  duration: Duration.quarter(), voice: VoiceId('melody'),
});
const original = builder.build();
const result = applyScoreOperations(original, [
  {type: 'move-notes', noteIds: [noteId], deltaQuarters: [1, 4]},
  {type: 'set-velocity', noteIds: [noteId], velocity: 96},
]);
console.log(original.getNote(noteId)?.onsetQuarters.toString()); // 0
console.log(result.score.getNote(noteId)?.onsetQuarters.toString()); // 1/4
```

### Written notation entry

`enter-notation` uses `ScoreNotationEntry`: a new `id`, existing `partId`,
`voice`, optional one-based `staff`, `onsetQuarters`, `duration`, and `pitch`.
`pitch` is the same spelled `{step, alter, octave}` as ordinary note insertion;
`null` enters a rest. Optional `velocity` sets a pitched note's authored
velocity. `ScoreNotationDuration` has `base: ScoreQuarterValue` and optional
`dots` (default `0`); supported bases are whole through sixty-fourth notes
(`[4,1]` through `[1,16]`), with zero, one or two dots. These are notation
values, so the sounded duration includes their dots.

Entry requires an existing positive authored measure containing the complete
duration. It does not infer measures from a MIDI time signature or extend the
piece. The selected measure/voice/staff must be simple and monophonic. Fully
covered notes are replaced; an overlap that would cut a sounding note is
rejected. Existing rests may be split, and remaining gaps become actual rests
with deterministic IDs and written durations. Other voices and staves remain
unchanged. Automatic completion requires exact gaps on a 1/64-quarter grid and
generates at most 256 rests per operation. It can use smaller rest values than
the offered input bases. One entry, including rest repair, is one atomic
operation. A controller entry commits one history item; a transaction containing
several entries shares one item, and the pure helper creates no history.

Ties, tuplets, grace notes, chords, authored beams, slurs, hidden or unpitched
notation, events crossing a measure boundary and unrepresentable rest gaps
are outside this entry subset. Replacing events with articulations, ornaments,
dynamics, lyrics or tags also rejects rather than discarding them. These
structures fail explicitly instead of silently losing notation. Stem
directions, rest positions and tie placement are display hints; a replacement
does not keep them. An entry whose result matches the replaced events apart
from generated IDs, such as re-entering an existing rest with its duration, is
a no-op. It keeps the existing notes, their IDs and any selection.

The [staff input controller](/score/headless/view/staff-editing/) supplies
cursor, duration and voice state for a custom interface over this same
operation; it does not create another Score or history.

### Document ports and commands

`ScoreDocumentSource` exposes `getSnapshot()` and synchronous `subscribe`.
`ScoreEditorPort` adds state, commands, history and interaction-session creation.
These interfaces live in Core so another capability can read a document without
depending on the editor implementation. Native ScorePlayer accepts the read-only
port; editable Score views require the command/session port.

`isScoreDocumentSource(value)` checks the required reader/subscriber methods and
the current snapshot: nonempty document/content identity, a nonnegative safe
revision, `ready` or `disposed` status and a Score instance. `isScoreEditorPort`
also checks every required state, command, history and session method. Both
return `false` for malformed values or throwing getters. These structural type
guards do not subscribe, mutate, or establish readiness: a disposed source can
satisfy the port shape, so consumers still inspect its snapshot status.

A `ScoreEditCommand` carries `version: 1`, `documentId`, `expectedRevision`,
`label` and `operations`. `execute` validates the complete serializable envelope
and commits atomically. `ScoreEditResult` is `committed` with a snapshot/change,
`noop` with the unchanged snapshot, or `failed` with a `ScoreEditError`. Command
errors are results; the pure helper throws. The [ScoreEditor reference](/score/headless/view/score-editor/)
owns revision, subscription, checkpoint and disposal details.

`ScoreDocumentSnapshot` contains `documentId`, `documentRevision`, `contentId`,
`content`, `status: 'ready' | 'disposed'`, and optional last `change`.
`ScoreDocumentChange` contains `origin`, `label`, from/to revisions, operations,
affected note IDs and a position map. Undo/redo/restore changes identify their
origin and do not replay the original edit operations.

### Position maps

Position maps describe content transitions in rational musical quarters. They
do not seek or reschedule a player.

| Function | Contract |
|---|---|
| `createScorePositionMap(documentId, fromRevision, toRevision, extent, policy?)` | Create a frozen map. Revisions are nonnegative safe integers with `toRevision > fromRevision`; `extent` is a nonnegative `Rational`. Policy defaults to `'preserve-quarter'`; `'reset-origin'` explicitly resets. |
| `composeScorePositionMaps(...maps)` | Require a nonempty, continuous revision chain for one document. Preserve intermediate clamps so an undo cannot reconstruct a lost position. The composed representation is bounded independently of undo history. |
| `mapScorePosition(map, position)` | Accept a nonnegative `Rational`; return `{quarters, clamped, positionPolicy}`. Preserved positions clamp to extent; reset policy returns the origin. |

Malformed maps or positions throw `ScoreEditError('invalid-command', ...)`.
A mismatched document or discontinuous composition throws `revision-conflict`.
The document source publishes maps with changes; consumers retain or compose
them themselves rather than expecting the editor to retain an unbounded log.

```ts
import {Rational} from '@webmusic/score';
import {createScorePositionMap, composeScorePositionMaps, mapScorePosition} from '@webmusic/score/view';

const shorter = createScorePositionMap('example', 0, 1, new Rational(2));
const restored = createScorePositionMap('example', 1, 2, new Rational(4));
const result = mapScorePosition(composeScorePositionMaps(shorter, restored), new Rational(3));
console.log(result.quarters.toString(), result.clamped); // 2, true
```

## Render a piano roll

`renderPianoRollVisualizer` draws the built-in SVG piano roll into an `<svg>` and returns the [renderer handle](#renderer-handle) used by `<score-view type="piano-roll">`.

```ts
import { renderPianoRollVisualizer } from '@webmusic/score/view/render';

const svg = document.querySelector<SVGSVGElement>('svg#piano-roll')!;
const rendered = renderPianoRollVisualizer(score, svg, {
  noteHeight: 12,
  noteSpacing: 2,
  pixelsPerSecond: 96,
  noteRGB: '17, 17, 17',
  activeNoteRGB: '217, 40, 40',
});

rendered.redraw(rendered.noteSequence.notes[0], true);
rendered.clearActiveNotes();
```

### Edit a piano roll

`mountPianoRollEditor(host, editing, options?)` mounts a written-quarter SVG
grid with selection, drag/resize/draw gestures, focused keyboard editing and
labeled numeric note controls. The `editing` argument is a
[`ScoreViewEditing`](/score/headless/view/score-view/#follow-an-editing-document)
controller over a borrowed Core editor port. It creates no editor, player or
clock. Plain note visualization remains on `renderPianoRollVisualizer`.

```ts
import {createScoreEditor, createScoreViewEditing} from '@webmusic/score/view/headless';
import {mountPianoRollEditor} from '@webmusic/score/view/render';

const editor = createScoreEditor(score);
const editing = createScoreViewEditing(editor, {editable: true});
const drawing = mountPianoRollEditor(document.querySelector<HTMLElement>('#notes')!, editing, {
  pixelsPerQuarter: 64,
  editingGrid: [1, 4],
  onCommit: (result) => console.log(result.snapshot.documentRevision),
});
// During teardown:
drawing.dispose();
editing.dispose();
editor.dispose();
```

| `PianoRollEditingOptions` member | Default | Contract |
| --- | --- | --- |
| `pixelsPerQuarter` | 64 | Finite positive pixel scale for written quarter positions. |
| `noteHeight` | 20 | Finite positive pitch-lane height in pixels. |
| `minPitch`, `maxPitch` | MIDI 48–84, expanded around notes | Safe integer bounds within 0–127, minimum no greater than maximum. A single explicit bound limits the computed opposite bound. |
| `editingGrid` | `[1, 4]` | Positive exact rational quarter grid for pointer and keyboard timing. |
| `noteColor`, `activeNoteColor` | Score View CSS tokens | CSS note fills; take precedence over the corresponding RGB channels. |
| `noteRGB`, `activeNoteRGB` | token fallback | Optional `"r, g, b"` fills when the corresponding CSS color is absent. |
| `onPreview(result)` | none | Successful preview `ScoreDraftResult`, including the revision-bound interaction snapshot. |
| `onCommit(result)` | none | Committed `ScoreEditResult`; no call for cancellation, failure or no-op. |
| `onError(error)` | none | Command or numeric-input failure. |

Mounting requires an available `editing` controller; otherwise it throws
`ScoreEditError` (`disposed`) before adding DOM or listeners.
`PianoRollEditingHandle` exposes `element` (the mounted section), `surface`
(the SVG, focusable while editable), `updatePlayback(snapshot?)`, `cancel()` and `dispose()`.
Playback updates draw time and active-note overlays only for ready, exactly
matching applied document identity/revision with `documentCoordinates: true`.
A playback-only update repaints the playhead and sounding notes on the existing
drawing.
Passing `undefined` removes playback overlays. `cancel()` discards the session
draft. Idempotent `dispose()` cancels this surface's active gesture, detaches its
listeners and resize observer and removes its DOM; it leaves the borrowed controller/editor alive.
A surface without an active gesture does not cancel another consumer's shared
draft on disposal. Render options are fixed for that mounted surface.

Where `ResizeObserver` is available, viewport size changes redraw newly visible
notes without editing the document. A size change cancels this surface's active
pointer gesture; it leaves another surface's shared draft intact.

The **Note values and keyboard alternatives** controls include a native
**Select existing note** menu, so keyboard users can choose an individual
existing note before applying numeric edits or deleting it. Options identify
part name/number, pitch, written-quarter onset, voice and note number, while
their values retain stable note identity; selection alone does not
commit content. The menu follows external selection and document changes,
displays a multi-selection summary and offers **No selection**. It retains
focus through updates; native menu keys do not run the grid's nudge shortcuts.
Numeric fields track the committed selected note and document revision;
selection or revision changes refresh that baseline. Other redraws preserve
unsubmitted values, including when focus leaves the form. Shared previews do
not replace the numeric baseline. Without a single selection, Apply is disabled
and the fields remain insertion parameters. Numeric, keyboard, history and pointer
commands capture their selection and document revision before cancelling a draft.
A selection or revision change during cancellation rejects the pending command
instead of applying captured values or history intent to newer content. Becoming
read-only, unavailable or disposed also stops the pending command. Pointer setup
rechecks the same context after focusing and selecting its target.

The grid works with ready empty content when a Part exists. It uses written
pitch and written quarters, even when imported notes have performed microtiming.
The [Element editing section](/score/element/view/score-view/#piano-roll-editing)
documents gestures, exact-value inputs, cancellation and supported semantic
limits. Notes, selection and drafts are rendered here; score annotations are
drawn only by the staff renderers.

### Edit a staff

`mountStaffEditor(host, input, options?)` composes the scrolling notation
renderer with a written-note cursor, note/rest selection, focused keyboard
input and labeled controls. The `input` argument is a borrowed
[`StaffViewEditing`](/score/headless/view/staff-editing/) controller, which
shares its underlying editor and history with other surfaces.

```ts
import {createScoreEditor, createScoreViewEditing, createStaffViewEditing} from '@webmusic/score/view/headless';
import {mountStaffEditor} from '@webmusic/score/view/render';

// score contains explicit authored measures and supported simple notation.
const editor = createScoreEditor(score);
const editing = createScoreViewEditing(editor, {editable: true});
const input = createStaffViewEditing(editing);
const drawing = mountStaffEditor(document.querySelector<HTMLElement>('#staff')!, input, {
  onCommit: result => console.log(result.snapshot.documentRevision),
  onError: error => console.error(error),
});
// During teardown:
drawing.dispose();
input.dispose();
editing.dispose();
editor.dispose();
```

`StaffEditingOptions` extends the existing `StaffRenderOptions`: notation
scale, spacing, split-staff layout, annotation visibility and paint options
keep their [staff-renderer defaults](#render-staff-notation).

| Additional option | Default | Contract |
| --- | --- | --- |
| `inputEnabled` | false | Initial armed note-input mode. It applies only while the controller is editable; `<score-view>` uses it to keep input armed across presentation re-renders. |
| `onCommit(result)` | none | Called for a committed `ScoreEditResult`; not for no-op or failure. |
| `onError(error)` | none | Reports command or input-field failures. |

`StaffEditingHandle` exposes `element` (the mounted section), `surface`
(the focusable input container), `updatePlayback(snapshot?)`, `cancel()` and
`dispose()`. If the controller cannot be subscribed, mounting removes its DOM and
rethrows. Playback overlays require exactly matching ready document identity
and revision, with authored coordinates; playback-only updates do not repaint
controls, selection or the live status. Passing `undefined` clears playback
overlays. `cancel()` exits note-input mode; every entry is already atomic and
there is no pending staff draft. Idempotent `dispose()` releases listeners,
the engraving surface and its DOM, leaving the borrowed controller/editor
alive. Rendering options are fixed for that mount.

The [Element's staff-input section](/score/element/view/score-view/#staff-input)
documents keys, fields and semantic limits. This adapter creates no playback
resource and does not infer authored measures from MIDI. The independent
`renderStaffVisualizer` remains available for passive rendering.

### Renderer handle

The render helpers return `RenderedScoreVisualizer<TVisualizer>`:

| Member | Contract |
| --- | --- |
| `noteSequence` | Read-only sequence used by this renderer. |
| `visualizer` | The underlying renderer instance. |
| `redraw(activeNote?, scrollIntoView?)` | Existing note-driven drawing entry. Exact-time-capable renderers use the nominated note’s onset; OSMD moves its engraving cursor. Returns a renderer coordinate or `null`. |
| `redrawAtTime?(nominalSeconds, scrollIntoView?)` | Optional exact-time drawing entry, implemented by the built-in SVG and Canvas piano rolls, waterfall and scrolling staff. Highlights notes where `startTime <= nominalSeconds < endTime`; it does not snap to a selected note’s onset. Returns a renderer coordinate or `null`. |
| `clearActiveNotes()` | Clear current highlights and the applicable cursor display. |
| `dispose?()` | Release owned rendering resources and DOM. Supplied by all package renderers and safe to repeat. |

`redrawAtTime` rejects non-finite time with `RangeError`. After disposal it is inert and returns `null`. Use nominal score seconds, without playback-rate scaling. `scrollIntoView: false` updates highlighting without requesting follow scrolling. Coordinate orientation and default following behavior belong to the selected renderer. OSMD retains `redraw` and does not implement `redrawAtTime`.

```ts
// On a caller-owned clock or position notification:
rendered.redrawAtTime?.(1.25, false);
```

## Render annotations

`StaffRenderOptions.showAnnotations` defaults to `true` for the scrolling
staff renderer. It reads the original Score's supported `Part.directions`:
words such as `rit.`, rehearsal labels, dynamics, metronome marks, pedal
signs/lines and crescendo/diminuendo hairpins, and keeps their authored
above/below placement around the notation. These are visual directions, with
no tempo, volume or sustain automation.

Annotations are staff-only. The piano-roll and waterfall renderers never draw
them and reserve no space for them; `VisualizerRenderOptions` and
`WaterfallRenderOptions` have no `showAnnotations` member, and
`validateScoreViewConfiguration` rejects it for `piano-roll` and `waterfall`.
Set `showAnnotations: false` on the staff to remove the marks and their layout
space; the natural staff height shrinks. Explicit application sizing still
defines the outer viewport.

The Element's [`show-annotations` attribute](/score/element/view/score-view/#annotations-and-compact-layout)
applies only to `type="staff"`. This is a rendering option; Headless
`createScoreView` continues to expose sounding-note state and does not allocate
an annotation surface. The [static thumbnail](#static-thumbnail) has its own
`showAnnotations` option for overview labels.

### Static thumbnail

`renderScoreThumbnail(surface, notes, options?)` appends a fitted SVG to a
caller-owned `HTMLElement` and returns that `SVGSVGElement`. `notes` is the
readonly `PianoRollNote[]` result of `createPianoRollLayout`; an empty array
returns `undefined` without drawing. A bare note layout has no expression
metadata, so supply `options.score` to draw the original Score's directions.

| `ScoreThumbnailRenderOptions` member | Default | Description |
| --- | --- | --- |
| `color` | `currentColor` | CSS fill for notes and annotations. |
| `label` | `Score preview` | Accessible name of the returned SVG. |
| `score` | absent | Original Score matching the note layout; supplies timed directions. |
| `showAnnotations` | `true` | Show directions when `score` is supplied; `false` removes their strip. |

With annotations, the drawing uses a `3rem` note preview plus a compact strip
measured at the surface's current width. Nearby directions form readable
overview groups with representative labels and counts; their titles retain all
source text and musical ranges. Text retains its size while the note plot fits
the remaining height, with a `1rem` minimum note area when annotations are
visible. Without annotations, the SVG fits the supplied surface.
This one-shot function creates no resize observer or player binding;
remove its returned SVG at teardown or before drawing again. Applications that
need responsive updates redraw it from their own resize handling; no
`<score-view>` type wraps this renderer.

```ts
import {createPianoRollLayout} from '@webmusic/score/view';
import {renderScoreThumbnail} from '@webmusic/score/view/render';

const surface = document.querySelector<HTMLElement>('#preview')!;
const drawing = renderScoreThumbnail(surface, createPianoRollLayout(score), {
  score,
  showAnnotations: true,
});
// Keep this callback for the owning surface's teardown.
const disposePreview = () => drawing?.remove();
```

## Render staff notation

`renderStaffVisualizer` accepts a parsed Score, including MusicXML imported
through `@webmusic/score/io`. `StaffRenderOptions.splitStaves` defaults to `true`:
each part's source staff assignments become separate layers. Set it to `false`
to combine staves within each part; different parts remain separate and the
source Score is unchanged. Layers align written onsets and share a scroll
position and playhead; the bottom timeline supplies manual scrolling.
`ScrollType.PAGE`, `NOTE` and `BAR` follow that shared position.

The renderer projects the original Score's rational written positions and
durations, including rests, spelled pitches, string voice identities, chords
and stored measure boundaries. This data is separate from the cached
sounding-note sequence used for activity. VexFlow 4.2.5 supplies the SVG glyphs;
WebMusic groups beams per voice, staff and measure, using source beam marks
before automatic metric grouping. Written tuplet ratios and group IDs control
numbers/brackets and source number visibility. Source up/down stems, hidden
spacing notes, ties and ordinary same-staff slurs are retained. Part-local
`clefChanges` apply at exact onsets, including within measures, and update the
fixed signature header while scrolling. Inference only applies when the staff
has no authored clefs; it limits ledger lines and avoids unnecessary changes.

Part `directions` draw words, rehearsal labels, dynamics, metronome marks,
pedal signs/lines and crescendo/diminuendo wedges. Spans pair by staff and
number across measures; their exact musical positions remain independent of
playback. Text placement and supported styles survive import. Hairpins leave
space for adjacent dynamics, and marks contribute to vertical staff clearance.
Ties and slurs are paired from source identity and laid out separately, using
head/stem-side attachments and surrounding glyph obstacles.

The drawing adds a system-start connector, plus braces and connecting barlines
for staves within the same part. Active highlighting includes noteheads and
their shared stems, flags and beams; a shared glyph stays active while any
associated note sounds.

Adjacent staves in one part use compact spacing based on the full score's glyph
bounds. Stems, ties and ledger lines keep their clearance even when currently
offscreen; notation is not scaled down to reduce the gap. Outer padding also
follows the drawing. `showAnnotations: false` excludes expressions from this
calculation while retaining notes, rests, clefs, key/time signatures, beams,
tuplets, ties, slurs and articulations.

A single full-height divider bounds the fixed signature area. The scrolling note drawing is clipped at this boundary to keep notes from overlapping clefs and signatures.

`BAR` follows the current beat when a complete measure cannot fit in the viewport. Resize and hidden-to-visible layout retain the latest following request; `redrawAtTime(time, false)` and a deliberate manual pan preserve their scroll position through resize.

Default spacing considers note and modifier geometry. A positive
`pixelsPerSecond` requests rhythmic spacing of `pixelsPerSecond × 60 / initialQpm`
pixels per quarter, with extra width where glyphs need it. The playhead maps
the complete tempo map onto engraved onset columns; this is not an exact
linear pixel/time ruler. `defaultKey` is a fallback chromatic major-key index
(0 = C, 1 = D♭, 2 = D), not a fifths count.

Stored notation is not rounded to a 1/16-quarter grid. MusicXML supplies written
relationships that timing-only MIDI or legacy sequences cannot recover.
Without usable written values, glyphs use readable duration/clef inference and
retain the exact stored onset timeline. `redrawAtTime` tests activity against
nominal sounding times, not the inferred glyph duration. File-to-Score
conversion limits remain owned by [I/O](/score/api/io/).

This scrolling renderer does not implement cross-staff/cross-measure beams,
nested tuplet layout, complete grace notation, lyrics or
page/system justification.
Retained metadata does not mean every mark is drawn. [OSMD](#render-with-osmd)
remains a separate optional page-engraving workflow.

```ts
import { renderStaffVisualizer } from '@webmusic/score/view/render';

const container = document.querySelector<HTMLDivElement>('#staff')!;
const rendered = renderStaffVisualizer(score, container, {
  splitStaves: true,
  showAnnotations: true,
  noteHeight: 7,
  noteSpacing: 1,
  pixelsPerSecond: 0,
  noteRGB: '17, 17, 17',
  activeNoteRGB: '217, 40, 40',
});

rendered.redraw(rendered.noteSequence.notes[0], true);
```

## Render a waterfall

`renderWaterfallVisualizer` draws falling notes on a vertical time axis, using
piano-style pitch columns without an embedded keyboard. Its default range is
A0–C8, with 20px natural-note columns and accidental columns 0.62 times as wide.
Set `showOnlyOctavesUsed: true` to use occupied MIDI octaves and `fitToWidth: true`
to fit the current container width. Positive explicit `whiteNoteWidth` or
`blackNoteWidth` values disable fitting and retain pixel column widths.
Setting only `blackNoteWidth` derives natural-note width by dividing by `0.62`;
accidental width is capped at natural width. Explicit `minPitch` / `maxPitch`
select exact MIDI endpoints before automatic octave selection. When composing
an independent keyboard, match those endpoints and widths and use a shared
horizontal scroller; see the [live aligned example](/score/element/view/score-view/#align-a-waterfall-and-keyboard).

The natural falling-note viewport follows score duration at the chosen time
scale, bounded to 80–200px. An explicit measurable container height uses the full
available height. Resizing reflows note columns while preserving the visible
score position and active notes; hidden containers retain their last useful
layout until a size is available. `dispose()` releases the resize observer (or
window-resize fallback) and owned DOM. The waterfall draws no score annotations.

```ts
import { renderWaterfallVisualizer } from '@webmusic/score/view/render';

const container = document.querySelector<HTMLDivElement>('#waterfall')!;
const rendered = renderWaterfallVisualizer(score, container, {
  noteSpacing: 2,
  pixelsPerSecond: 64,
  whiteNoteWidth: 16,
  showOnlyOctavesUsed: true,
});

rendered.redraw(rendered.noteSequence.notes[0], true);
```

`WaterfallVisualizerConfig` controls falling-note geometry and optional fitting;
it has no keyboard presenter port. `whiteNoteHeight` and `blackNoteHeight` are
not supported render options and `configure()` rejects them. Applications that
also need a keyboard compose a separate
[`<score-pitch-view type="keyboard">`](/score/element/view/score-pitch-view/) or UIKit pitch
presenter around the same borrowed player state.

`VisualizerRenderOptions.noteColor` and `activeNoteColor` accept full CSS colors, including custom-property expressions. They override the corresponding `noteRGB` / `activeNoteRGB` channel strings. The imperative renderers retain neutral defaults: `noteRGB: '96, 96, 96'` and `activeNoteRGB: '32, 32, 32'`.

The published note-renderer factories and `<score-view>` draw SVG. Colors remain live CSS values: host or ancestor class/token changes update existing notes without a source reload, a cursor reset or an additional animation loop. Their SVG drawing backgrounds remain transparent; the application or composing UIKit stage owns the surrounding surface.

The styled [`<score-view>`](/score/element/view/score-view/) supplies its own defaults. Its active color is `var(--wm-score-view-active-note, var(--wm-accent, rgb(240, 84, 119)))`: the specific token precedes the shared accent, with the existing red as the final fallback. Changing the Element’s default does not change the imperative renderer palette.

## Sync a visualizer to playback

`bindPlayerToVisualizer(rendered, subscribe, controller?)` accepts an application-supplied event adapter. It retains held notes across individual releases and clears highlights on end; it does not create a player or clock. This note-event helper uses `redraw`. For continuous exact-time highlighting, drive `redrawAtTime` from the application’s nominal position notifications.

```ts
import {bindPlayerToVisualizer} from '@webmusic/score/view/render';
import {createScorePlayer} from '@webmusic/score/play/headless';
import {noteMidi, noteOnsetSeconds} from '@webmusic/score';

const player = createScorePlayer(score);
const unbind = bindPlayerToVisualizer(rendered, ({noteOn, noteOff, end}) => {
  const offOn = player.on('noteOn', note => noteOn(noteMidi(note), noteOnsetSeconds(note, score)));
  const offOff = player.on('noteOff', note => noteOff(noteMidi(note), noteOnsetSeconds(note, score)));
  const offEnd = player.on('end', end);
  return () => { offOn(); offOff(); offEnd(); };
});
// … unbind() when the view goes away
```

To do it by hand instead — or to highlight from a source that is not a player
— subscribe to `noteOn` yourself and call `redraw` with the matching sequence
note. `findSequenceNote` locates the rendered note by MIDI pitch and onset.

```ts
import { findSequenceNote } from '@webmusic/score/view';
import { renderPianoRollVisualizer } from '@webmusic/score/view/render';
import { createScorePlayer } from '@webmusic/score/play/headless';
import { noteMidi, noteOnsetSeconds } from '@webmusic/score';

const rendered = renderPianoRollVisualizer(score, svg);
const player = createScorePlayer(score);

player.on('noteOn', (note) => {
  const seqNote = findSequenceNote(rendered.noteSequence, noteMidi(note), noteOnsetSeconds(note, score));
  rendered.redraw(seqNote, true);
});
player.on('end', () => rendered.clearActiveNotes());

await player.play();
```

## Create layout data

Use layout functions when you want serializable geometry and plan to draw with your own renderer: SVG, Canvas, WebGL, native UI, or a design-system component.

Used layout scales must be finite and positive; invalid `pixelsPerSecond`,
`laneHeight` or `staffSpace` values throw `RangeError`, including for empty
scores. `pixelsPerSecond` defaults to 30. Piano-roll `laneHeight` defaults to
6 pixels; waterfall uses it as natural-note column width (default 20), with accidental columns
two-thirds as wide. Waterfall columns retain A0 (MIDI 21) at `x = 0` and extend
across MIDI 0…127; pitches below A0 have negative `x`, which a renderer can
translate into its own viewport. Recompute geometry when your chosen scale
changes; these functions own no resize observer or pixel-to-time input adapter.

`createStaffLayout` uses written diatonic steps relative to middle C, with one
half staff-space per step and separate vertical origins for parts. Its
`ledgerLines` value is a distance heuristic without a clef model; this projection
is not a MusicXML engraving layout. Use the notation render adapters for clefs,
staff structure and engraved glyph placement.


```ts
import { createPianoRollLayout, createStaffLayout, createWaterfallLayout } from '@webmusic/score/view';

const pianoRoll = createPianoRollLayout(score, { pixelsPerSecond: 80, laneHeight: 8 });
const staff = createStaffLayout(score, { pixelsPerSecond: 60, staffSpace: 10 });
const waterfall = createWaterfallLayout(score, { pixelsPerSecond: 80, laneHeight: 18 });

const values = {
  pianoRoll: pianoRoll.slice(0, 3).map((item) => ({
    pitch: item.note.pitch.toString(),
    x: item.x,
    y: item.y,
    width: item.width,
    height: item.height,
  })),
  staff: staff.slice(0, 3).map((item) => ({
    pitch: item.note.pitch.toString(),
    x: item.x,
    staffY: item.staffY,
    ledgerLines: item.ledgerLines,
  })),
  waterfall: waterfall.slice(0, 3).map((item) => ({
    pitch: item.note.pitch.toString(),
    x: item.x,
    y: item.y,
    startSeconds: item.startSeconds,
    durationSeconds: item.durationSeconds,
  })),
};
```

Output:

```json

    { "pitch": "E4", "x": 20, "y": 80, "width": 19, "height": 8 },
    { "pitch": "G4", "x": 40, "y": 56, "width": 19, "height": 8 }
  ],

    { "pitch": "C4", "x": 0, "staffY": 0, "ledgerLines": 0 },
```

## Whole-score map data

`createScoreMap` uses **quarter notes**, rather than the layouts' nominal
seconds. Its `maxCells` (default 64) and `maxMarks` (default 24) must be finite;
they are rounded and clamped to at least one, while non-finite values throw
`RangeError`. Major rehearsal, tempo and meter landmarks survive mark thinning,
so `maxMarks` is a target rather than a strict total limit. Density counts
overlapping sounding note spans, including held notes crossing a cell boundary;
it is neither loudness nor a harmonic estimate. Cells cover the complete
non-negative score extent, including notes before, between and after supplied
measures. Unmeasured intervals have no invented measure numbers; measured and
unmeasured spans share the same `maxCells` budget. Overlapping measures form one
non-overlapping span, with the actual first/last encountered measure numbers.
Zero-duration measures remain eligible ruler marks without zero-width cells.


```ts
import {createScoreMap} from '@webmusic/score/view';

const map = createScoreMap(score, {maxCells: 32, maxMarks: 16});
console.log(map.durationQuarters, map.cells, map.marks);
```

`ScoreMapOptions.part` filters counts by part ID or name; an unmatched part has
zero density while timeline coverage remains. `ScoreMapCell` carries
`startQuarters`, `endQuarters`, `count`, `density` (`0…1`) and optional
`firstMeasure`/`lastMeasure`. `ScoreMapMark` carries `startQuarters`, `label`
and `level: 'major' | 'minor'`. `ScoreMap` contains `durationQuarters`, `cells`
and `marks`; an empty score produces empty arrays.

For source attachment and delegated navigation, compose
[createScoreMapView](/score/headless/view/score-map-view/). The pure projection
owns no player subscription, cursor or seek command.

## Current-pitch projections

These exports from `@webmusic/score/view` turn MIDI values into reusable data
without a Score, chord analysis or UI. Use them with
[createPitchView](/score/headless/view/pitch-view/) or your own held-note state.
The arrays deduplicate and sort supplied MIDI pitches; tuning order is preserved.
No pitch is moved to another octave and no guitar fingering is inferred.

```ts
import {currentStaffMarks, currentFretMarks, readoutPitch} from '@webmusic/score/view';

const midis = [60, 63, 67];
console.log(readoutPitch(63, 'flat').toString()); // Eb4
console.log(currentStaffMarks(midis, 'flat'));
console.log(currentFretMarks(midis, [40, 45, 50, 55, 59, 64], 0, 12, 'flat'));
```

| Export | Contract |
| --- | --- |
| `readoutPitch(midi, spelling = 'sharp')` | Returns a root-model `Pitch` in the requested sharp/flat spelling. |
| `currentStaffMarks(midis, spelling = 'sharp')` | Returns `CurrentStaffMark[]`: MIDI, stable ID, written label, diatonic step, optional accidental, `active: true` and `column: 0`. |
| `currentFretMarks(midis, tuning = STANDARD_VIEW_TUNING, firstFret = 0, frets = 12, spelling = 'sharp')` | Returns every exact-MIDI position within the inclusive fret interval `[firstFret, firstFret + frets]`. A pitch outside that window has no mark. |
| `STANDARD_VIEW_TUNING` | Frozen low-to-high open-string MIDI array `[40, 45, 50, 55, 59, 64]`. |
| `PitchReadoutSpelling` | `'sharp' \| 'flat'`; no automatic key inference. |
| `CurrentStaffMark` | `{midi, id, label, diatonic, accidental?, active: true, column: 0}`. `diatonic` is octave × 7 plus the C-based letter index; accidental is `'sharp'` or `'flat'`. |
| `CurrentFretMark` | `{midi, stringIndex, fret, label, mark, active: true, id}`. String index follows supplied tuning order, fret is semitones above that string, label includes the octave and mark omits it. |

MIDI inputs must be integers in `0…127`; tuning has 1–12 such values.
`firstFret` must be an integer in `0…24`, and `frets` an integer in `1…24`.
Invalid pitches, tuning, spelling or fret geometry throw `RangeError` before
returning a projection. The helpers own no subscriptions or disposal work.

## Convert to a note sequence

`scoreToNoteSequence` converts a `Score` into the internal view-model used by the visualizers. Use `findSequenceNote` to locate the rendered note that matches a MIDI pitch and start time.

The conversion is cached by immutable Score identity and returns frozen data.
It describes sounding notes; explicit rests and full written notation remain
in the source Score. Staff rendering additionally projects that original Score
instead of reconstructing beams, tuplets or clefs from the flattened sequence.
Notes are sorted by nominal onset and then pitch. `findSequenceNote` expects
that sorted order and returns the first matching pitch/onset within a strict
one-microsecond tolerance; it does not distinguish simultaneous unisons. For
exact part/note identity and all matching active notes, use the Headless view's
playback observation.

`secondsToQuarters(tempos, seconds)` integrates the sequence's full tempo map;
`qpm` means quarter notes per minute, including any source beat-unit conversion.
It sorts unordered markers without mutating them, extends the first tempo to
the origin, uses 120 qpm for an empty map, and clamps negative time to zero.
Seconds must be finite, marker times finite and non-negative, and qpm finite
and positive; violations throw `RangeError`. Mutable marker arrays are re-read
on every call. This converts nominal score time, not rate-scaled transport time.

```ts
import { findSequenceNote, scoreToNoteSequence } from '@webmusic/score/view';

const sequence = scoreToNoteSequence(score);
const active = findSequenceNote(sequence, 60, 0);

const values = {
  ticksPerQuarter: sequence.ticksPerQuarter,
  notes: sequence.notes.length,
  totalTime: sequence.totalTime,
  firstNote: sequence.notes[0],
  active,
  partInfos: sequence.partInfos,
};
```

Output:

```json
{
  "ticksPerQuarter": 480,
  "notes": 8,
  "totalTime": 2,
  "firstNote": {
    "pitch": 60,
    "velocity": 63,
    "startTime": 0,
    "endTime": 0.25,
    "instrument": 0,
    "program": 0,
    "part": 0,
    "staff": 1
  },
  "partInfos": [{ "part": 0, "name": "Piano" }]
}
```

## Render with OSMD

`renderOSMDStaffVisualizer` renders full notation engraving through OpenSheetMusicDisplay. The dependency is optional, and `@webmusic/score/view` does not convert scores to MusicXML by itself — pass pre-serialized MusicXML (e.g. `serializeMusicXML` from `@webmusic/score/io`) or a converter function.

Install `opensheetmusicdisplay` to let a browser bundler resolve the lazy peer
import, or inject `OpenSheetMusicDisplay`/`osmd` as shown below. Native browser
modules need an import map or constructor injection. Importing the renderer
does not evaluate the optional engine until rendering is requested.

For an owned OSMD instance, the adapter reflows when its container width changes, using `ResizeObserver` or a window-resize fallback. Height-only changes do not re-engrave the score. Disposal releases the observer and pending resize work; a borrowed instance retains its existing lifecycle.

For this adapter, `redraw(undefined, false)` cancels queued cursor scrolling without moving or clearing the cursor. `clearActiveNotes()` and disposal also invalidate pending scrolling. An explicit `redraw(note, true)` still requests scrolling when the default `followCursor` option is false.

Backward cursor moves reset and replay OSMD’s iterator, reacquiring the replacement iterator created by `reset()` before applying checkpoints. This adapter continues to expose note-driven `redraw`, rather than `redrawAtTime`.

```ts
import { renderOSMDStaffVisualizer } from '@webmusic/score/view/render';
import { OpenSheetMusicDisplay } from 'opensheetmusicdisplay';

const rendered = await renderOSMDStaffVisualizer(score, document.querySelector('#osmd'), {
  musicXML,
  OpenSheetMusicDisplay,
  osmdOptions: {
    drawTitle: false,
    drawPartNames: false,
  },
});

rendered.redraw(rendered.noteSequence.notes[0], true);
```

Output:

```txt
Score + MusicXML + OSMD constructor -> RenderedScoreVisualizer<OSMDLike>
```

## Mode-specific configuration

`ScoreViewConfiguration` is a discriminated union of `{type, options?}` for
`piano-roll`, `staff` and `waterfall`. `ScoreViewOptionsByType` maps each mode to
its renderer options; `piano-roll` also accepts the editor-bound grid's
`pixelsPerQuarter` and `editingGrid`, which passive renderers ignore. These types prevent options for one mode from silently
configuring another.

`validateScoreViewConfiguration(configuration): void` validates the mode and
option keys without creating UI. It throws `TypeError` for an unknown mode,
malformed options or an unsupported key. It does not replace each renderer's
value/default semantics. The Element's
[`configure()`](/score/element/view/score-view/) uses this check before changing
its mode or options; legacy permissive option bags remain supported.
`showAnnotations` is accepted only for `staff`.
