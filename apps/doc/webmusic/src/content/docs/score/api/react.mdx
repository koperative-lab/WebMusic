`@webmusic/score/react` is the React binding capability of the `@webmusic/score` package. It gives you two levels of API:

- Ready-made modules for direct JSX usage, such as `<SimpleScorePlayer score={score} />`.
- Lower-level Provider, hooks, and view components for custom application design.

It expects your app to provide a `Score` object. It does not import files or create a standalone app shell.

`PianoRollView`, `StaffView` and `WaterfallView` also work without a provider:
pass `score` for a static drawing, or `playback` to borrow an existing
[`ScorePlaybackSource`](/score/api/#shared-playback-observation). These forms
create no player or audio resource. The `Simple*` presets and `ScoreProvider`
retain their owned-player behavior.

## Install

`npm install @webmusic/score react` — use an available published version or the local workspace; [Install](/score/#install) has the full setup.

React is a peer dependency:

```txt
react >= 18
```

  return (

      score={score}
      className="score-player"

    />

## AnalysisSummary

Use `AnalysisSummary` when you want a compact packaged summary of key, chords, roman numerals, motifs, and voice-leading issues.

An empty score displays `Unknown` for the key. The underlying analysis retains
its compatibility placeholder, but an empty candidate list supplies no evidence
for a detected key. Nonempty estimates are heuristic rankings, not calibrated
probabilities; see the [Analyze API](/score/api/analyze/).

You can pass `score` directly:

```tsx
import type { Score } from '@webmusic/score';
import { AnalysisSummary } from '@webmusic/score/react';

export function Page({ score }: { score: Score }) {
  return <AnalysisSummary score={score} className="analysis" />;
}
```

Or render it inside `ScoreProvider`:

```tsx
import type { Score } from '@webmusic/score';
import { AnalysisSummary, ScoreProvider } from '@webmusic/score/react';

export function Page({ score }: { score: Score }) {
  return (
    <ScoreProvider score={score}>
      <AnalysisSummary className="analysis" />
    </ScoreProvider>
  );
}
```

## Customize With Provider

Use `ScoreProvider` directly when you want one shared score/player context and full control over the layout.

```tsx
import type { Score } from '@webmusic/score';
import { ScoreProvider } from '@webmusic/score/react';

export function App({ score }: { score: Score }) {
  return (
    <ScoreProvider
      score={score}
      playerOptions={{
        tempo: 96,
        synth: {
          noteOn(midi, velocity, time, durationSeconds) {
            console.log('on', midi, velocity, time, durationSeconds);
          },
          noteOff(midi, time) {
            console.log('off', midi, time);
          },
        },
      }}
    >
      <CustomWorkspace />
    </ScoreProvider>
  );
}
```

Provider output:

```txt
ScoreProvider
  -> ScoreContext
  -> PlayerContext
  -> CursorContext
```

## Customize With Hooks

Use hooks inside `ScoreProvider` to build custom controls, readouts, analysis panels, or editor UI.

```tsx
import { useCursor, usePlayer, useScore, useScoreAnalysis } from '@webmusic/score/react';

export function CursorReadout() {
  const score = useScore();
  const player = usePlayer();
  const cursor = useCursor();
  const analysis = useScoreAnalysis({ windowQuarters: 4 });

  return (
    <button type="button" onClick={() => player.seek(0)}>
      {score.metadata.title}: {analysis.key.tonic} {analysis.key.mode}, measure {cursor.measure}, beat {cursor.beat.toFixed(2)}
    </button>
  );
}
```

Hook output:

```txt
useScore()              -> Score
usePlayer()             -> Player
useCursor()             -> { tick, seconds, measure, beat }
useScoreAnalysis()      -> { key, chords, roman, motifs, issues }
useScoreAnalysisAsync() -> { result, pending }
```

For large scores, `useScoreAnalysisAsync` runs the same analysis off the main thread in a Web Worker (see [Analysis in a Worker](/score/api/analyze/#analysis-in-a-worker)). Instead of blocking the render it returns `{ result, pending }`: `result` is the latest finished analysis (`null` until the first one lands), `pending` is true while the current score is being analyzed. Edits are coalesced latest-wins — rapid successive edits only analyze the newest score — and when `Worker` is unavailable (SSR, tests) the hook falls back to an in-process session. The worker is disposed on unmount. Pass the same options as `useScoreAnalysis`, plus an optional `worker` (instance or factory) for custom bundler setups:

```tsx
const { result, pending } = useScoreAnalysisAsync({ windowQuarters: 4 });
if (result) console.log(result.key.tonic, pending ? '(updating…)' : '');
```

Hooks must be called inside `ScoreProvider`:

```txt
useScore must be used inside ScoreProvider
usePlayer must be used inside ScoreProvider
useCursor must be used inside ScoreProvider
```

## Customize Individual Components

Use the lower-level components when you want to compose your own workspace but still want packaged React wrappers around the view layer.

```tsx
import type { Score } from '@webmusic/score';
import {
  AnalysisSummary,
  PianoRollView,
  PlayerControls,
  ScoreProvider,
  StaffView,
  WaterfallView,
  useCursor,
  useScore,
} from '@webmusic/score/react';

function StatusBar() {
  const score = useScore();
  const cursor = useCursor();

  return (
    <output>
      {score.metadata.title} · measure {cursor.measure} · beat {cursor.beat.toFixed(2)}
    </output>
  );
}

export function CustomWorkspace({ score }: { score: Score }) {
  return (
    <ScoreProvider score={score}>
      <PlayerControls className="transport" />
      <StatusBar />
      <AnalysisSummary className="analysis" />
      <PianoRollView width={720} height={240} className="piano-roll" />
      <StaffView width={720} height={220} className="staff" />
      <WaterfallView width={720} height={320} className="waterfall" />
    </ScoreProvider>
  );
}
```

Component tree:

```txt
ScoreProvider
  PlayerControls
  StatusBar
  AnalysisSummary
  PianoRollView
  StaffView
  WaterfallView
```

## Static views and external playback

Use the same low-level views when sound belongs to an application engine. No
hidden element, selector, provider or manual DOM event is needed:

```tsx
import type {Score, ScorePlaybackSource} from '@webmusic/score';
import {StaffView} from '@webmusic/score/react';

export function StaticScore({score}: {score: Score}) {
  return <StaffView score={score} />;
}

export function FollowingScore({playback}: {playback: ScorePlaybackSource}) {
  return <StaffView playback={playback} />;
}
```

| Props | Data and ownership |
| --- | --- |
| `score` | Draw this immutable score statically, including inside a provider. |
| `playback` | Borrow the source's current score, nominal position and note activity; follow source replacement. |
| `score` + `playback` | Keep the explicit score; follow only ready snapshots with that exact Score identity. A mismatch or unavailable source remains static and clears the borrowed projection. |
| Neither | Inherit the `ScoreProvider` score and its player's shared playback source. Outside a provider, the view reports `empty`. |

Snapshots initialize the view synchronously on subscription, including a paused
position. Time-aware renderers show the cursor and score notes at that position,
including when playback is paused. OSMD maps nominal seconds through the score
tempo map to its next available cursor position at or after that time (or the
end). Its cursor is discrete, not a continuous position within a note or rest.
Later seeks and rate changes use nominal score seconds, without
starting another timer or forwarding seek commands. Replacing a source or
unmounting a view releases its subscription and drawing resources only; it
never stops or disposes borrowed playback. Unsubscribe failure does not skip
renderer cleanup. Source callbacks arriving after detach are ignored.

The score identity check also applies when MIDI drives a separate MusicXML
score: the application must supply an explicitly mapped source whose snapshots
refer to the displayed score and its part/note IDs. Matching pitches, URLs or
duration alone does not establish a correspondence. This API does not infer
repeat mappings, create a playback source for an arbitrary engine, or add
playback observation to `InteractivePlayer`.

## Render readiness and failures

All three views accept `onStateChange(state)`. Its immutable
`ScoreViewRenderState` is also exported from `@webmusic/score/react` and
[`@webmusic/score/view/render`](/score/api/view/). It reports readiness of this
view's drawing, independently of the audio engine:

```tsx
import type {Score} from '@webmusic/score';
import {StaffView, type ScoreViewRenderState} from '@webmusic/score/react';

export function ObservedScore({score, onStateChange}: {
  score: Score;
  onStateChange: (state: ScoreViewRenderState) => void;
}) {
  return <StaffView score={score} onStateChange={onStateChange} />;
}
```

| Field | Contract |
| --- | --- |
| `status` | React views publish `empty`, `loading`, `rendering`, `ready`, `error` or `disposed`. Static data normally transitions from `rendering` to `ready`. |
| `phase` | `source` for borrowed loading/readiness or subscription failure, `render` for drawing, and `null` for a static empty view or disposal. React views do not parse files or publish the shared type's `load` phase. |
| `revision` | Increases for each state publication in this mounted view. |
| `generation` | Identifies a source/render attempt. Replacement and effect cleanup invalidate previous asynchronous work. |
| `score` | The selected score, when available. A source may retain one during `loading` or `error`; neither status means the view is ready. |
| `cause` | Original source/render failure when available, including OSMD rejections. |

`ready` means the current drawing has been constructed. A borrowed source's
`ready` state alone does not establish it. When the source supplies the data,
source `loading`/`error` and unavailable/disposed sources clear the old drawing
and report `loading`/`error` or `empty`, respectively. An explicit `score` stays
renderable under those source states; its rendering can be `ready` while the
borrowed source is unavailable, with no playback projection. Observe the source
itself for source errors in that mode. A renderer failure releases the failed drawing;
replace the score/source or change rendering options to retry.

OSMD completion and failure from superseded or unmounted generations are
ignored, and late handles are disposed. A callback may replace the source
without allowing the obsolete generation to publish `ready`. Effect cleanup
reports `disposed`, including before a replacement effect and during React
StrictMode's cleanup/remount check. Changing only the callback does not recreate
the renderer. Callback and cleanup exceptions are reported to `console.error`;
source/render errors are logged there when no callback is supplied. Hosts own
translated loading/error UI and retry controls.

## Annotation visibility

`PianoRollView`, `StaffView` and `WaterfallView`, and their `Simple*` presets,
accept `showAnnotations` (default `true`) for the packaged SVG renderers. Set it
to `false` to hide words, dynamics, tempo, rehearsal, pedal and hairpin marks
and remove their reserved space. Notes and notation essentials remain visible.
`StaffView` and `WaterfallView` retain their explicit/default viewport heights;
use `height="auto"` on `StaffView` to follow its compact natural drawing height.
OSMD engraving remains configured through its own `osmdOptions`.

## OSMD Staff Mode

`StaffView` and `SimpleStaff` use the lightweight staff renderer by default. Pass `osmd` when you want OpenSheetMusicDisplay engraving.

```tsx
import { SimpleStaff } from '@webmusic/score/react';
import { OpenSheetMusicDisplay } from 'opensheetmusicdisplay';

<SimpleStaff
  score={score}
  osmd={{
    musicXML,
    OpenSheetMusicDisplay,
    osmdOptions: {
      drawTitle: false,
      drawPartNames: false,
      autoResize: true,
    },
  }}
/>;
```

Output:

```txt
SimpleStaff without osmd -> lightweight staff renderer
SimpleStaff with osmd    -> OpenSheetMusicDisplay renderer
```

## Styling

Preset and low-level components accept `className` props and render normal DOM nodes. Every visible
component already owns the same outer surface: a white background, `1px solid #d8d8d8` border,
`.6rem` padding, and square corners. Override the shared tokens when an application needs a different
theme; no documentation wrapper or page rule is required. The seek track's line follows the shared
`--wm-control-border` → `--wm-border` → `#d8d8d8` chain, while the primary play button keeps its
black fill and border.

```css
.music-ui {
  --wm-component-background: #fff;
  --wm-component-border: 1px solid #d8d8d8;
  --wm-component-padding: 0.6rem;
  --wm-component-radius: 0;
}
```

Rendered roots:

```txt
PlayerControls -> div
AnalysisSummary -> dl
PianoRollView  -> div -> scroll viewport -> svg
StaffView      -> div
WaterfallView  -> div
```

## API Reference

| API | Kind | Use it for |
| --- | --- | --- |
| `SimpleScorePlayer` | Preset | Render `ScoreProvider` + `PlayerControls` from a `score` prop. |
| `SimplePianoRoll` | Preset | Render `ScoreProvider` + `PianoRollView` from a `score` prop. |
| `SimpleStaff` | Preset | Render `ScoreProvider` + `StaffView` from a `score` prop. |
| `SimpleWaterfall` | Preset | Render `ScoreProvider` + `WaterfallView` from a `score` prop. |
| `SimpleScoreWorkspace` | Preset | Render controls, optional analysis, and score views from a `score` prop. |
| `AnalysisSummary` | Component | Render a compact key/chord/roman/motif/voice-leading summary. |
| `ScoreProvider` | Provider | Provide `Score`, `Player`, and cursor state to child components. |
| `useScore()` | Hook | Read the current `Score` from context. |
| `usePlayer()` | Hook | Read the shared `Player` instance from context. |
| `useCursor()` | Hook | Read the latest `{ tick, seconds, measure, beat }` cursor position. |
| `useScoreAnalysis(options?)` | Hook | Read key, chord, roman, motif, and voice-leading analysis from context. |
| `useScoreAnalysisAsync(options?)` | Hook | The same analysis off the main thread in a Web Worker: `{ result, pending }`. |
| `PlayerControls` | Component | Render a simple play/pause button and range input. |
| `PianoRollView` | Component | Render a static SVG piano roll or follow shared playback snapshots. |
| `StaffView` | Component | Render static or playback-connected lightweight staff notation or OSMD engraving. |
| `WaterfallView` | Component | Render static or playback-connected falling-note pitch columns, without an embedded keyboard. |
| `ViewProps` · `StaffViewProps` | Types | Static/borrowed `score` and `playback`, render-state callback, layout, accessibility and styling props; Staff adds `osmd`. |
| `ScoreViewRenderState` · `ScoreViewRenderStatus` · `ScoreViewRenderPhase` | Types | Observable presentation readiness, generation and original failure. |
