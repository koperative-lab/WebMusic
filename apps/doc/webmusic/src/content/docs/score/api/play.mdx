    await ready;

    const now = performance.now() / 1000;
    const dt = last ? now - last : 0;
    last = now;
    player.advance(dt ? { secondsPerBeat: dt } : {});
  } catch (error) {
    ready = undefined;
    console.error('Playback preparation failed', error);
  }
};
document.body.append(tap);`;

## The playback stack

A player is one instrument, composed of three pluggable layers:

```txt
<player · score · sound · effect>
          │        │       └ Effect — post-processing (reverb, delay, filter…)
          │        └ Sound  — timbre (oscillator, samples, .sfz, .sf2, custom)
          └ Score          — the notes (from a file or built in code)
```

For many instruments, give each its own player and group them in a **`Rack`**. Two engines sit at opposite ends, chosen by *who owns time*:

| You want | Use |
| --- | --- |
| Autonomous timeline playback (pure Web Audio) | **`ScorePlayer`** (push) |
| External-signal / beat-at-a-time interaction, live score swap | **`InteractivePlayer`** (pull) |
| Many instruments, each its own score/sound/effect, played together | **`Rack`** |
| A progress-bar / scrub / rate widget | **`ScorePlayer`**'s transport surface + the `bind*` drivers |

## SFZ data and recording conversion

`parseSfz(text, options?)` flattens supported `<global>`, `<group>` and
`<region>` opcodes into `SfzRegion[]`. `parseSfzKey(value)` accepts numeric keys
and note names (`c4` is MIDI 60); an unrecognized spelling returns `undefined`.
This is a limited opcode parser, not a complete SFZ interpreter.

`resolveSfzZones(regions, sfzUrl, options?)` resolves sample paths and produces
`SampleZone[]`. Missing `lokey`, `hikey` and `pitch_keycenter` independently
default to 0, 127 and 60. Setting a range boundary does not change the root
pitch; the explicit `key` shorthand sets all three values. These defaults match
the SFZ definitions for [key ranges](https://sfzformat.com/opcodes/lokey/),
[the upper boundary](https://sfzformat.com/opcodes/hikey/) and
[sample root](https://sfzformat.com/opcodes/pitch_keycenter/).

`SfzParseOptions.maxInputCharacters` defaults to 1,000,000 and `maxRegions`
defaults to 512, also exposed by the frozen `DEFAULT_SFZ_PARSE_LIMITS` object.
Limits must be positive safe integers. Parsing rejects a non-string source with
`TypeError`; invalid limits or exceeded budgets throw `RangeError`.
Zone resolution accepts only the `maxRegions` option and omits regions without
a sample. None of these functions fetches or decodes audio.

`notesToScore(notes, options?)` accepts `RecordedNote` values with `midi`,
`velocity`, `voice`, `onsetSec` and `durationSec`. It creates one part per voice,
preserves performed seconds and velocity, and derives notated quarters at
`bpm` (default 120). `ppq` is a positive safe integer tick resolution (default
480); `title` defaults to `Recording`. A finite positive `quantizeGrid` snaps
onsets and durations to that many quarters; zero, negative or omitted values
disable snapping. Notated durations are at least one tick, including a captured
zero-duration note. The generated measures use 4/4.

Invalid tempo, PPQ, non-finite quantization, negative or non-finite captured
timings, and derived timing beyond the supported measure range throw
`RangeError` before allocating measures. Empty recordings still validate
options and produce one empty measure. The conversion owns no recording device,
player or clock.

## Note-input mappings

`qwertyMidi(code, baseC)` returns the mapped MIDI number or `null` for an
unmapped physical-key code. Only the map's own key entries are considered;
inherited object names do not map to notes. `gridKeyboardMidi` and
`gridQwertyCellMidi` share that lookup and their existing explicit-pad fallback.

`parseGridMap(text)` reads sparse `ref=midi` pairs separated by commas,
semicolons or whitespace, using refs such as `a1` and `z10`. Empty, malformed
or non-finite assignments are ignored without clearing an earlier mapping;
numeric zero remains a valid value. Finite values are rounded, with the last
valid assignment for a cell winning. This mapping helper does not clamp MIDI
range; callers choose and validate the playable range for their input surface.

### Parsing off the main thread

Parsing large files blocks the main thread — measured ~160ms for a 20k-note MusicXML and ~360ms for a 100k-note MIDI. `createParserWorker()` moves the parse into a Web Worker: the worker posts back plain Score JSON and the main thread only pays the cheap `scoreFromJSON` rebuild (~50ms), so the UI stays responsive.

```ts
import {createParserWorker} from '@webmusic/score/io/worker-client';

const parser = createParserWorker();

// Bytes / text you already have — caller-owned buffers are never detached.
const score = await parser.parse(buffer); // format sniffed; or parse(data, 'midi')

// Fetch happens on the main thread (page cookies, relative URLs), parse in the worker.
const fromUrl = await parser.loadFromUrl('/scores/sonata.mxl');

parser.dispose(); // terminate the worker when done
```

After checking `maxInputBytes`, `parse*()` snapshots the caller's `ArrayBuffer`
or exact `Uint8Array` range once. A real Worker receives that private snapshot
by transfer; the fallback parses the same snapshot. URL loading may transfer
its own bounded response buffer directly. Every route preserves caller
ownership and never mutates or detaches the original.

By default the worker is spawned with the bundler-friendly pattern `new Worker(new URL('./worker.js', import.meta.url), {type: 'module'})`, which Vite / webpack / Rollup detect and bundle automatically. If your bundler can't handle it, pass your own `Worker` instance or factory:

```ts
const parser = createParserWorker(
  () => new Worker(new URL('@webmusic/score/io/worker', import.meta.url), {type: 'module'}),
);
```

Where `Worker` doesn't exist (Node, SSR) — or constructing one throws — every call transparently falls back to in-process parsing behind the same Promise API, so the code is safe to run anywhere. The worker protocol itself (`ParseRequest` / `ParseResponse` and the pure `handleParseRequest`) is exported too, in case you want to host the handler in your own worker.

### Browser adapter composition

```ts
// Each browser adapter returns a cleanup; retain every binding you install.
import { bindScroll, bindPointer, bindOrientation } from '@webmusic/score/play/drivers';

const offScroll = bindScroll(player, { mode: 'position' });
const offPointer = bindPointer(player, surfaceEl, { axis: 'x' });
const offOrientation = bindOrientation(player, { axis: 'gamma' });

offScroll();
offPointer();
offOrientation();
```

Here `player` is a compatible continuous transport such as `ScorePlayer`,
not the `InteractivePlayer` in the earlier independent example. These
browser adapters own their installed event bindings; the transport and
target elements remain caller-owned.

## API Reference

| --- | --- | --- |
| `createScorePlayer` / `ScorePlayer` / `Player` | Engine | Autonomous push-clock timeline engine. |
