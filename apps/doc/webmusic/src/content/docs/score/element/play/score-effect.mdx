`<score-effect>` declares one insert in the selected module's chain. The declaration
renders nothing; use an attached panel to edit its realized parameters. The
shared example below includes both Score and Audio declarations on one bus.

<ModularCompositionDemo />

## Import

```html
<script type="module">
  import {defineScoreEffectElement} from '@webmusic/score/play/element';
  defineScoreEffectElement();
</script>

<score-effect id="filter" target="#desk" type="filter" frequency="1200"></score-effect>
<score-synth-panel target="#filter" sections="effects"></score-synth-panel>
```

Register the target owner and Score panel through their owning entries as in
[the runnable composition](/bridge/modular-composition/). The target must expose
an `InsertChain`; an explicit missing target stays pending. Without `target`,
the nearest module context supplies the owner: a player owns its local insert,
a rack/mixer supplies its master insert. Ordinary HTML `slot` has no routing
semantics here.

<details class="component-section">
<summary>API</summary>

### Declaration and target

| Member | Contract |
| --- | --- |
| `type` | Recipe kind, default `gain`; unknown kinds report an error. |
| `target` | Unique module selector in the current root; discovery follows replacement without preparing audio. |
| `.moduleTarget` | `ModuleHandle`, `null`, or `undefined`. Object wins; null unbinds; undefined resumes selector/context lookup. |
| `.effect` | Custom domain `Effect` recipe; overrides the built-in type and numeric attributes. Assign undefined to restore declaration recipes. |
| `.slotId` | Stable declaration identity. Changing the DOM id does not transfer the realized insert. |
| `.module` | Read-only borrowed module of the exact realized `EffectInstance`, including its `ParamSurface`; absent until the owner is prepared. |

### Type parameters

Numeric attributes require finite values and apply only to the selected recipe.
Changing a recipe attribute replaces that slot transactionally. Editing its live
`ParamHandle` changes the existing instance in place.

| Type | Attributes | Meaning/defaults |
| --- | --- | --- |
| `gain` | `gain` | Linear gain. |
| `panner` | `pan` | Stereo pan. |
| `filter` | `filter-type`, `frequency`, `q`, `gain` | Biquad mode, Hz, Q and dB. |
| `delay` | `time`, `feedback`, `wet`, `dry` | Delay seconds and linear gains. |
| `reverb` | `seconds`, `decay`, `wet`, `dry` | Impulse duration/decay and mix. |
| `compressor` | `threshold`, `ratio`, `knee`, `attack`, `release` | dB threshold/knee, ratio and seconds. |
| `limiter` | `threshold`, `release` | dB threshold and release seconds. |
| `tremolo` | `frequency`, `depth` | Modulation Hz and depth. |
| `chorus` | `time`, `frequency`, `depth`, `wet` | Delay seconds, modulation Hz and mix. |
| `distortion` | `amount` | Distortion amount. |
| `bitcrusher` | `bits` | Quantization depth. |

### Events and ownership

Failures use `webscore:error`; invalid candidates retain the previous working
chain. The chain owns realized effect instances and their nodes. The declaration
owns its slot membership, and a panel owns only UI/subscriptions. Multiple panels
can therefore edit the same instance without constructing another effect.

Declarations append in initial attachment order. A synchronous same-scope DOM
layout move retains the slot and instance; an actual removal drops this slot at
the next microtask. Replacing a source or owner releases obsolete connections.
Neither discovery nor an attribute change forces audio preparation.
