Inspect complete, spelled triads and seventh chords, including their bass and inversion. Score mode collects notes by metrical pulse by default, with exact simultaneous inspection available; live mode reads the selected player’s held MIDI notes. Choose the mode in external Parameters. Degree labels require an explicit key and never infer harmonic function.

## Import

```html
<script type="module">
  import {defineScorePlayerElement} from '@webmusic/score/play/element';
  import {defineChordAnalysisElement} from '@webmusic/score/analyze/element';
  defineScorePlayerElement();
  defineChordAnalysisElement();
</script>

<score-player id="piece" src="/mxl/Arabesque%20No.1.mxl"></score-player>
<score-chord-analysis player="#piece" window="1"></score-chord-analysis>
```

Registration is idempotent and SSR-safe. `defineAllAnalysisElements()` registers all four tools from the same entry; see the [family inventory](/score/element/#analyze). This demo contains one player and one inspection surface. Its one-second initial window leaves room for complete chord and note labels; adjust `window` to change the visible passage without changing the musical grouping. External Parameters configures them; Copy includes their actual markup and Reset restores attributes and the player connection. Optional sibling views belong in [an application composition](/score/element/#compose-a-performance).

## Musical reading

Score mode defaults to `grouping="beat"`: each half-open metrical pulse collects every source note overlapping it, including sequential notes and notes sustained from an earlier pulse. Simple 2/3/4 meters use one denominator unit per pulse; compound 6/9/12 meters use groups of three. Other numerators require `beat-groups`, such as `2+3` for 5/8; list one grouping per irregular numerator, such as `2+3 2+2+3` for 5/8 and 7/8. Each grouping applies to the numerator equal to its sum, conventional meters keep their pulses unless a grouping sums to them, and an irregular meter without a matching grouping reports an error. `grouping="simultaneous"` instead reads exact positive-duration spans between note boundaries and ignores a retained `beat-groups` setting. The stateless API and Headless projection keep simultaneous inspection as their default.

Complete triads and supported seventh chords are matched by spelling; doublings are allowed, but missing roots, omitted tones and enharmonic reinterpretations are not invented. Beat collections retain passing tones and all other overlapping pitches even when these prevent a match. Unmatched sets show their pitch names. The displayed bass/inversion uses the lowest collected source pitch; a beat collection does not establish the passage’s structural harmonic bass. A deterministic first candidate is a reading, not a probability. `key="C major"` or `key="A minor"` adds a scale-relative Roman degree, chord quality and inversion figure; it does not infer a key, modulation, cadence or harmonic function. Minor degrees use the explicit natural-minor reference.

Beat grouping can expose notes distributed across an arpeggio, but it is not an automatic harmonic reduction: actual harmonic duration may span several beats, and non-chord-tone interpretation requires more context. The [API method reference](/score/api/analyze/#inspect-elementary-chord-structure) explains the source evidence and musical limits.

Live mode updates its nameplate immediately from held notes. MIDI lacks authored spelling, so `spelling` and explicit key context choose display spellings; this inferred spelling cannot recover an original score's notation. Live MIDI pitches are already sounding values, so `pitch-mode` applies only to score inspection. Live mode ignores score/source input and has no score seek or history lane. Silence and unclassified sets leave `.chord` undefined. `webscore:chordchange` waits for a stable named chord; changing notes, reset or source replacement cancels pending notification. Switching modes changes this component's surface without changing the player's state.

The live surface starts with the large chord name, followed by quieter source note names with octaves. It omits the spelling explanation from the performance display; that explanation remains here. An unmatched set keeps the chord row empty and its notes below. Silence shows `—`. Reserved chord, note and optional alternate-reading rows keep the layout steady as held notes change; long lines can scroll horizontally without ellipses. Alternate readings remain secondary text, controlled by `alternates` in Parameters.

The demo loads the existing [Arabesque No. 1 score](/mxl/Arabesque%20No.1.mxl), shared by all four tools. Select a pulse to inspect its actual collected pitches and any complete chord reading, then compare `grouping="simultaneous"` to see exact overlapping sets. Leave `beat-groups` unset for the piece’s conventional meters; unmatched collections retain their pitch names. Switch to live mode to follow the same player’s held notes. Set an explicit key only when you want that reference for degree labels; the component does not infer it from the piece.

`spellingInferred` in underlying note evidence marks spelling inferred during analysis-time transposition only. It does not detect spelling chosen earlier by an importer; a false flag cannot establish authored spelling for a MIDI-origin Score.

Named chords appear above their source pitch names, including octaves. An unmatched collection leaves the chord-name row empty and keeps its pitch names in the quieter note row below, in both the current readout and timeline. Live mode uses the same separation. No placeholder chord or collection caption is shown. Grouping stays in external Parameters and `.analysis.detail`; it is not repeated in the visual readout. An explicit key adds its degree/reference only to a named chord's current reading. Timeline labels wrap and rows grow to fit their text instead of using ellipses; the full current reading also wraps above the timeline. Bands narrower than 48px, for example under a long `window`, hide their labels instead of wrapping single characters; their reading stays in the band title, the current readout and the semantic list, and such bands do not make the rows taller. Rows with offscreen-only material are hidden, with one empty row retained through gaps; this layout does not change the collected notes or their evidence.

## Binding and lifetime

Explicit `.score` wins over `src`, then the selected player's resolved Score. Native bindings prefer the player's `.playback` [shared source](/score/api/#shared-playback-observation), including its initial readiness, data, position and note identities. Late, upgraded or replaced targets are rebound. Invalid or ambiguous selectors stay unbound. Targets without an available native source retain the compatibility snapshot/event path; they do not promise an initial snapshot.

Failed explicit loading does not fall back to unrelated player data; empty input and errors are shown by the surface. Superseded loads cannot restore old input. An explicit Score different from the native player's Score suppresses mismatched activity and cannot seek that owner. Pointer selection and keyboard navigation use `seekNominal()` when available, otherwise convert nominal seconds by the current rate before `seek()`. Failed commands restore the previous local position unless newer state has arrived. Standalone navigation still emits a seek request.

The component owns its URL request, analysis projection, target observer, subscriptions and presenters. Disconnect cancels/releases those resources. The player retains its lifetime, Score, sound and authoritative timeline. No Analyze component creates a player, synth, AudioContext or playback scheduler.

`ChordAnalysisElement`, `AnalysisSelection`, `AnalysisInspection`, `AnalysisSeekDetail` and `AnalysisSelectDetail` are exported from `@webmusic/score/analyze/element`.

`selectRegion(startQuarters, endQuarters)` selects a finite increasing quarter-note passage without seeking. It clamps to the loaded Score, throws `RangeError` for invalid/wholly out-of-score bounds, and has no effect without a Score. `clearSelection()` returns to the first available band. Neither method edits notes or commands playback. In live mode `.selection` and `.analysis` are undefined and region selection has no effect. `selectNotes()` is unsupported and throws `TypeError`. `src`, `.score`, `motion` and `window` remain available for returning to score mode.

### Events and accessibility

All emitted events bubble and are composed.

| Event | Detail | Trigger |
| --- | --- | --- |
| `webscore:seek` | `AnalysisSeekDetail`: `{quarters, seconds}` | Lane navigation; quarter notes and nominal score seconds. |
| `webscore:analysisselect` | `AnalysisSelectDetail`: `{kind: 'chord', id, startQuarters, endQuarters}` | Band/region selection; local inspection state. |
| `webscore:chordchange` | `{chord, midis}` | A named live chord remains stable for the configured delay. |

Pending URL loads or a native player's loading state show the shared four-square loading
animation. Missing input shows the slower square waiting animation. Their descriptions remain
available to screen readers; load failures and empty analysis results retain visible text.

The score lane is a named slider tab stop. Arrow keys, Home/End and `[` / `]` navigate; pointer selection chooses a band and seeks. A semantic ordered list marks the current span with `aria-current`; detailed selection evidence has a nonvisual status. Passive playback does not repeatedly announce a local selection. The chord's live nameplate exposes text and has no navigation controls. Display configuration remains outside the component, and automatic motion respects reduced-motion preference.
