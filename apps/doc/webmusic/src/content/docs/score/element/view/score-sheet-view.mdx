`<score-sheet-view>` engraves a score as sheet music. Measures are broken into
systems that fill the line, each system restates its clef and key, and systems
are laid out on paper pages or in one continuous column. With a borrowed
editor and `editable`, it works like a notation program: select notes and
rests, move pitches, write notes in input mode and change durations. For a
compact scrolling staff use [`<score-view type="staff">`](/score/element/view/score-view/);
for DAW-style note editing use [`<score-grid-view>`](/score/element/view/score-grid-view/).

The demo loads Arabesque No. 1 from MusicXML (`public/mxl/Arabesque No.1.mxl`)
into one editor. The page owns that editor and lends it to the player and the
sheet. Every switch and setting is in **Parameters**; the toolbar's layout and
zoom buttons and Ctrl/Cmd + and − update **layout** and **zoom** there. Reset
restores the attributes and reloads the piece, discarding edits.

## Import

```html
<script type="module">
  import {defineScorePlayerElement} from '@webmusic/score/play/element';
  import {defineSheetViewElement} from '@webmusic/score/view/element';
  import {loadScoreEditor} from '@webmusic/score/view/headless';
  defineScorePlayerElement();
  defineSheetViewElement();
  // Your page owns the editor; dispose it after detaching the elements.
  const editor = await loadScoreEditor('/mxl/Arabesque%20No.1.mxl');
  const player = /** @type {import('@webmusic/score/play/element').ScorePlayerElement | null} */ (document.getElementById('sheet-player'));
  const sheet = /** @type {import('@webmusic/score/view/element').SheetViewElement | null} */ (document.querySelector('score-sheet-view'));
  if (player) player.editor = editor;
  if (sheet) sheet.editor = editor;
</script>

<score-player id="sheet-player"></score-player>
<score-sheet-view input="#sheet-player" editable></score-sheet-view>
```

A read-only sheet needs only data: `<score-sheet-view src="/mxl/Arabesque%20No.1.mxl"></score-sheet-view>`.
No optional peer is involved; engraving uses the package's own staff engraver.

## Ports and composition

`<score-sheet-view>` is a **View** companion. It declares no ports and provides no module
context to children. It borrows the position, sounding notes and, without an editor, the `webmusic.score` source of one Score playback owner — a
`<score-player>` or a `<score-rack-part>` — and sends no transport commands. It
never registers with or creates a Session.

| Connection | Form | Behavior |
| --- | --- | --- |
| Containment | Nested inside a player or Rack part | Borrows the nearest one; no attribute needed |
| Explicit input | `input="#id"` | One unique element in the same Document or ShadowRoot |
| Explicit module | `.inputModule = module` | Follows that module's `source` port (`webmusic.score`), or the one `port` names; `null` unbinds |
| Module port | `port="source"` with `input` or containment | Follows the named source port on the selected or enclosing module instead of the owner element |
| Explicit data | `.editor`, `.score`, `src` | Takes precedence over borrowed data; `.editor` excludes the other two |

Playback resolves `.inputModule`, then the explicit selector, then containment, then nothing; a `port` attribute moves the selector or containment onto that module's source port. Views and analysis share one follower, so they see the same notes, position and readiness. An
`input` that is missing, invalid or ambiguous stays unbound, reported by
`data-player-state`, and never falls back to the enclosing scope. Inside a
source-free outer player, nest the view in the member that plays or name that
member with `input`.

```html
<score-player src="/mxl/Arabesque%20No.1.mxl">
  <score-sheet-view layout="flow"></score-sheet-view>
</score-player>
```

## Data and layout

Data comes from `.score`, `src`, the input player's score, or a borrowed
`.editor`, with the same precedence and conflicts as
[`<score-view>`](/score/element/view/score-view/). MusicXML or MXL gives the
best notation: MIDI carries no key signature, staff assignment or spelling, so
those are inferred.

| Layout | Drawing |
| --- | --- |
| `page` (default) | A4 paper pages stacked in a scrolling desk. The first page carries the title and composer from the score's metadata. With `zoom` absent a page fits the element width. |
| `flow` | Systems as wide as the element, one after another, without pages. |

Measures are spaced by duration, broken into systems at the line width and
justified, except a short last system. Every system starts with its clef, key
signature and brace, and its first measure number; a time signature appears
where the meter changes. Beams, tuplets, ties, slurs, articulations, clef
changes and supported directions come from the [staff engraver](/score/element/view/score-view/#annotations-and-compact-layout).
A tie or slur that crosses a system break is not drawn. `zoom` scales the
staff (0.5–3); a width change re-breaks the systems.

Zoom never re-engraves a page: in `page` layout the systems break the same at
every zoom, so the engraved pages are scaled with CSS `zoom` and stay
vector-sharp. A trackpad pinch or Ctrl/Cmd+wheel zooms around the pointer and
follows the fingers; while it moves it is a compositor transform of the laid-out
pages, and it is laid out once when it settles, then reported. In `flow` layout
the systems fill the width at the engraved scale, so they are re-broken once a
zoom settles.

## Editing

Editing needs a ready `.editor` and `editable`; the toolbar then appears along
the top. `tools` lists the offered features — `pitch`, `input`, `duration`,
`tie`, `accidental`, `delete`, `history`, `zoom` (absent means all). Selection
and navigation are always available. A feature that is not offered leaves the
toolbar and stops its keys and gestures.

Each edit is one atomic editor command, so undo, the editor's history and a
bound player follow it. Edits work locally on the notes you point at, inside
real scores with several voices, chords, beams and slurs:

| Feature | Edit | Behavior |
| --- | --- | --- |
| `pitch` | Arrow keys, dragging a notehead | Up/Down move a semitone, spelled in the key first, then as a natural, then sharp going up and flat going down. Ctrl/Cmd moves an octave; Alt+Shift moves one diatonic step in the key. Dragging moves diatonically by staff position. A tied note moves its whole tie chain. |
| `input` | N, A–G, 0, clicking the staff | Note input mode writes at a cursor in the selected note's voice. A letter writes that pitch class in the key at the octave nearest the previous note; 0 writes a rest; a click writes the clicked staff position. The cursor advances by the written value. |
| `duration` | 1–7, `.` | With a selection outside input mode, the event's value changes; a shorter value leaves rests, a longer one replaces what follows within the measure. In input mode they set the value to write. 1 is a sixty-fourth note through 7, a whole note; `.` toggles a dot. |
| `tie` | `+` | Ties a note to the next note of the same pitch in its voice, or removes that tie. In input mode it writes the same pitch at the cursor, tied. |
| `accidental` | Flat, natural, sharp buttons | Respell the selected notes with that alteration. |
| `delete` | Delete, Backspace | Selected notes become rests of the same written value and tuplet; in a chord only the chosen heads go. |
| `history` | Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z or Ctrl/Cmd+Y | Undo and redo through the borrowed editor. |
| `zoom` | Zoom buttons, Ctrl/Cmd + and −, Ctrl/Cmd+wheel and trackpad pinch | Change `zoom`; the page and continuous view buttons change `layout`. |

Click selects a note or rest; Ctrl/Cmd+click adds or removes one; Shift+click
selects the range in the same voice. Left/Right move the selection, or the
input cursor, to the previous or next event; Escape leaves input mode, then
clears the selection.

Rewriting a rhythm needs a measure at the cursor and stays inside it. Tuplet
rhythms, grace notes and notes crossing a barline cannot be rewritten yet; such
an edit is refused with a short message in the toolbar and an `editerror`
event, and the score is unchanged. Pitch changes, accidentals and deletion
work on tuplet notes too. Chords, additional voices and tuplet entry are not
offered.

## Playback

`input` selects one player in the same Document or ShadowRoot; without it, the
sheet follows the enclosing player or Rack part. Sounding notes
take the active ink and a cursor marks the position in its system;
`follow-cursor` (default on) scrolls the sounding system into view. The sheet
never sends playback commands. With an editor, the player contributes time only
while its applied document matches the editor's committed revision, as for
[`<score-grid-view>`](/score/element/view/score-grid-view/#playback).

| Member | Kind | Default | Description |
| --- | --- | --- | --- |
| `src` / `format` | attributes | none | Explicit MIDI / MusicXML / MXL / ABC URL and optional parser override. Conflicts with `.editor`. |
| `input` | attribute | containment | Unique selector of a player or Rack part to follow; without other data the sheet borrows its score. |
| `port` | attribute | owner element | Follow this named `webmusic.score` source port on the input (or enclosing) module instead of the owner element; also names the port of `.inputModule` (default `source`). |
| `width` / `height` | attributes | 100% / natural | Bare numbers are px; CSS lengths pass through. |
| `layout` / `.layout` | attribute / property | `page` | `page` or `flow`; other values read as `page`. |
| `zoom` / `.zoom` | attribute / property | fit (`0`) | Staff size factor clamped to 0.5–3. Absent, zero or invalid fits a page to the width (page) or uses 1 (flow). |
| `follow-cursor` / `.followCursor` | attribute / property | true | Scroll the sounding system into view. |
| `editable` / `.editable` | boolean attribute / property | false | Enable editing for a ready `.editor`; never creates one. |
| `tools` / `.tools` | attribute / property | every feature | Offered features, space- or comma-separated: `pitch`, `input`, `duration`, `tie`, `accidental`, `delete`, `history`, `zoom`. Unknown tokens are ignored; the getter returns them in that order. |
| `note-color` / `active-note-color` | attributes | sheet tokens | Notation ink and sounding ink as `#rgb`, `#rrggbb`, `rgb()` or `r, g, b`. |
| `.score` | writable property | none | Assign a loaded Score; overrides `src` and borrowed input data. Throws while `.editor` is assigned. |
| `.inputModule` | writable property | none | Explicit module input; follows its `source` port, or the one `port` names, before `input` and containment. `null` unbinds, `undefined` returns to discovery. |
| `.editor` | writable property | none | Borrow any `ScoreEditorPort`; never disposed. `undefined` detaches it. |
| `.interactionSession` | writable property | sheet-owned session | Borrow a same-document session to share selection and drafts, for example with a grid. |
| `.currentTime` | read-only property | 0 | Current nominal score position in seconds. |
| `data-editor-state` / `data-editable-state` / `data-playback-state` / `data-player-state` | reflected state | absent | As on [`<score-grid-view>`](/score/element/view/score-grid-view/). |

**Events.** All are `CustomEvent`s that bubble and are composed.

| Event | `detail` | When |
| --- | --- | --- |
| `editpreview` | `ScoreDraftResult` with `status: 'preview'` | A notehead drag produced a valid draft. |
| `editcommit` | `ScoreEditResult` with `status: 'committed'` | An edit committed. |
| `editerror` | `{error}` | An edit the score cannot take, such as a tuplet rhythm. |
| `sheetsettingschange` | `{settings, changed}`: the `ScoreSheetSettings` (`layout`, `zoom`, `inputMode`, `duration`, `dotted`) and the changed key | The toolbar or keyboard changed a setting; `layout` and `zoom` are also reflected to their attributes. |

```ts
import {defineSheetViewElement, type ScoreSheetSettingsChangeDetail, type SheetViewElement} from '@webmusic/score/view/element';

defineSheetViewElement();
const sheet = document.querySelector<SheetViewElement>('score-sheet-view')!;
sheet.tools = ['pitch', 'delete', 'history'];
sheet.addEventListener('sheetsettingschange', (event) => {
  const {settings, changed} = (event as CustomEvent<ScoreSheetSettingsChangeDetail>).detail;
  console.log(changed, settings[changed]);
});
```

`SheetViewElement`, `defineSheetViewElement(tag?)`, `SHEET_VIEW_FEATURES` and
the types `ScoreSheetFeature`, `ScoreSheetLayout`, `ScoreSheetDuration`,
`ScoreSheetSettings` and `ScoreSheetSettingsChangeDetail` are exported from
`@webmusic/score/view/element`. Registration is idempotent and SSR-safe. The
element mounts [`mountScoreSheet`](/score/api/view/#mount-a-score-sheet) from
`@webmusic/score/view/render`.

**Lifecycle.** Disconnect cancels a pending load and an active drag, releases
the engraving, its listeners and resize observer, and the sheet-owned session.
The borrowed editor, a supplied session and the player stay alive.

**Accessibility.** An editable sheet's pages are one focusable region described
by instructions that list the keys, and a polite live status announces the
selected or written note and refused edits. Both are read by assistive
technology but not drawn. Icon buttons carry accessible names and tooltips and
report their pressed state; the note-value button opens a modal card that keeps
focus until it closes. Selection draws a frame around the notes, so it does not
rely on color. A read-only sheet is outside the tab order.
