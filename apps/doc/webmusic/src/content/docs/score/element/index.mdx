The drop-in custom elements of `@webmusic/score` — place a tag on the page, no
JavaScript wiring required. Each capability ships its elements from its
`/element` subpath, so the capability root tree-shakes free of DOM code. To load
and register them — via a CDN script, a bundler, or individual `define*` calls —
see [Score setup](/score/#drop-in-web-components). Only Play publishes `/auto`
and `/global`. Register the analyze and view tags
with the `define*` functions listed in their sections below.

| Capability | Elements |
| --- | --- |
| [Play](#play) | Playing a score: the transport, a rack mixer, note input, recording and synth control. |
| [Analyze](#analyze) | Elementary inspection: chord score/live modes, intervals, explicit scales and grouped rhythm. |
| [View](#view) | Whole-score representations with optional editing, held-pitch representations and optional sheet engraving. |

## Play

The elements of [`@webmusic/score/play`](/score/api/play/). **Five interactive elements and one effect declaration cover the capability**, with an individual reference and live demo for each.

| Element | Job |
| --- | --- |
| [`<score-player>`](/score/element/play/score-player/) | **Play a score back.** Load a file or assign a `Score`; play/pause, seek, emit note events. Drive a whole `Rack` via `.rack`, or assign `.controller` to drive an engine you already own. |
| [`<score-rack-control>`](/score/element/play/score-rack-control/) | **Mix a rack.** Master and per-member volume faders for a shared `Rack`. |
| [`<score-note-input>`](/score/element/play/score-note-input/) | **Play notes by hand.** One element with three layouts — piano / grid / chords — plus optional QWERTY control through `keyboard`. |
| [`<score-recorder>`](/score/element/play/score-recorder/) | **Capture a performance.** Record note input into a `Score`, replay it, download MIDI / MusicXML. |
| [`<score-synth-panel>`](/score/element/play/score-synth-panel/) | **Shape the sound.** Timbre, effect chain, ADSR, EQ, LFO and macro knobs in one panel; the `sections` attribute picks which areas render, so `sections="eq"` is an EQ on its own. |

Transport and mixing are deliberately separate: point [`<score-player>`](/score/element/play/score-player/) and [`<score-rack-control>`](/score/element/play/score-rack-control/) at one shared `Rack`.

The input surfaces share one tiny contract — bubbling `webscore:noteon` / `webscore:noteoff` `CustomEvent`s (`{ midi, velocity }`) plus an optional `.onNote(midi, velocity, on)` callback — so any of them wires to any player or a `Sound.midiOut`. For the programmatic engines, timbres, effects, and ensemble behind them, see the [Play API](/score/api/play/).

Each element page has a live demo, API details and styling variables.
[`<score-recorder>`](/score/element/play/score-recorder/) captures note events from
[`<score-note-input>`](/score/element/play/score-note-input/) or another event source; the
recorder page owns that composition and its recording contract.

| Element | Register | Job |
| --- | --- | --- |
| [`<score-player>`](/score/element/play/score-player/) | `defineScorePlayerElement(tag?)` | Load a file or assign a `Score`; play/pause, seek, emit note events. |
| [`<score-rack-control>`](/score/element/play/score-rack-control/) | `defineRackControlElement(tag?)` | Mixer (master + per-member volume faders) for a shared `Rack`. |
| [`<score-note-input>`](/score/element/play/score-note-input/) | `defineNoteInputElement(tag?)` | Discrete note surface — `layout` piano / grid / chords, `keyboard` for QWERTY. |
| [`<score-recorder>`](/score/element/play/score-recorder/) | `defineScoreRecorderElement(tag?)` | Record note input → `Score`, replay, download MIDI / MusicXML. |
| [`<score-synth-panel>`](/score/element/play/score-synth-panel/) | `defineSynthPanelElement(tag?)` | Control panel — `sections` sound / effects / envelope / eq / lfo / macros. |
| — | `defineAllElements()` | Register every element at its default tag (what `@webmusic/score/play/auto` calls). |

### Effect declarations and module scope

[`<score-effect>`](/score/element/play/score-effect/) is a nonvisual insert declaration,
registered by `defineScoreEffectElement()` from `@webmusic/score/play/element` and included
in the auto-registration entry. Every player is a module scope
(DEC-068): the outermost player owns the Session, nested players borrow it
unless `session="local"`, and nested effects, note inputs, panels, views and
analysis connect to the nearest provider by containment. Each Element page has
a **Ports and composition** section with its ports and explicit forms;
[the shared example](/bridge/modular-composition/) shows inherited transport,
master inserts, attached parameter panels and output taps.

## Analyze

Choose one tool for the musical question you want to inspect. Each tag renders
one surface, can borrow an enclosing or `input`-named player, and keeps its own selection without
editing the score.

| Purpose | Component | What it does |
| --- | --- | --- |
| Inspect chord structure | [`<score-chord-analysis>`](/score/element/analyze/score-chord-analysis/) | Score or live mode: complete triads/sevenths, bass and inversion; degrees only with an explicit key. |
| Compare two notes | [`<score-interval-analysis>`](/score/element/analyze/score-interval-analysis/) | Spelled melodic or harmonic intervals, direction, semitones and note provenance. |
| Compare notes with a scale | [`<score-scale-analysis>`](/score/element/analyze/score-scale-analysis/) | Explicit tonic and major/minor form; degree and alteration without guessing a key. |
| Locate an attack in meter | [`<score-rhythm-analysis>`](/score/element/analyze/score-rhythm-analysis/) | Duration, measure, grouped beat and subdivision in simple, compound or explicitly grouped meter. |

Whole-score summaries, histograms and rhythmic-vocabulary reports use the [Headless report workflow](/score/api/analyze/#reports). [Motif search](/score/api/analyze/#find-motifs), [recurring rhythmic phrases](/score/api/analyze/#find-recurring-rhythmic-phrases), [key estimates](/score/api/analyze/#detect-key), specialist [Roman analysis](/score/api/analyze/#roman-numerals) and [voice-leading checks](/score/api/analyze/#voice-leading) remain code-only building blocks. These four elementary tools describe supplied evidence; they do not guess tonal function or grade musical correctness.

### Compose a performance

```html
<script type="module">
  import {defineScorePlayerElement} from '@webmusic/score/play/element';
  import {defineChordAnalysisElement} from '@webmusic/score/analyze/element';
  import {definePitchViewElement} from '@webmusic/score/view/element';
  defineScorePlayerElement();
  defineChordAnalysisElement();
  definePitchViewElement();
</script>

<score-player id="piece" src="/midi/Arabesque%20No.1.mid"></score-player>
<score-chord-analysis input="#piece"></score-chord-analysis>
<score-pitch-view type="keyboard" input="#piece" low="48" high="84"></score-pitch-view>
<score-pitch-view type="staff" input="#piece" system="grand"></score-pitch-view>
```

The player loads once. Score-based companions borrow its resolved data and position; pitch views borrow its held notes. Each is an ordinary sibling that can be placed, styled or omitted independently. Configuration belongs to each tag’s attributes and application-owned controls. Each tag-owned live demo pairs that Analyze component with one player; the example above shows an optional composition. No Analyze component mounts an internal keyboard, staff, fretboard, tab bar or settings dock.

Score input precedence is explicit `.score`, then `src`, then the input player’s resolved data. Score lanes also work with standalone input: they update local inspection and emit seek requests without creating playback resources. When bound, navigation goes to the existing player with explicit nominal/transport time conversion. Selecting analysis evidence is local to that tool. The chord component in `mode="live"` reads sounding note activity and does not seek score time. Its default `mode="score"` shares the same data/selection contract as the other three score lanes.

### Shared input connection

Native bindings consume the [nonvisual playback source](/score/api/#shared-playback-observation).
They obtain data and an initial snapshot before waiting for another note/time
event, and follow replacements without fetching the player's URL again. Explicit
`.score` takes precedence over `src`, then borrowed input data. Failed explicit
loading does not silently fall back to another source. When explicit data differs
from a native player's Score, navigation rejects the mismatch rather than seeking
with unrelated geometry. Omit the companion `src` to share the loaded Score.

A companion nested inside a `<score-player>` or `<score-rack-part>` borrows it by
containment, without any attribute. `input="#id"` instead selects one unique
target in the same Document or ShadowRoot. Resolution runs explicit selector,
then containment, then none; an `input` that is missing, invalid or ambiguous
stays unbound and never falls back to the enclosing scope. Discovery follows
late insertion, upgrade and replacement until disconnect. The read-only
`data-player-state` attribute exposes target resolution (`missing`, `invalid`,
`ambiguous`, `ready`) and native source readiness. Legacy events remain usable
when a target has no source or reports `unavailable`, including custom player
renderers. They cannot supply resolved data or an initial snapshot automatically.
When a native source is available, legacy events are ignored to avoid duplicates.

A custom target may expose `.playback` and dispatch a bubbling
`webmusic:sourcechange` when replacing that property. Disconnecting releases
subscriptions, discovery and owned analysis work, without stopping the player.

| Element | Register |
| --- | --- |
| [`<score-chord-analysis>`](/score/element/analyze/score-chord-analysis/) | `defineChordAnalysisElement(tag?)` |
| [`<score-interval-analysis>`](/score/element/analyze/score-interval-analysis/) | `defineIntervalAnalysisElement(tag?)` |
| [`<score-scale-analysis>`](/score/element/analyze/score-scale-analysis/) | `defineScaleAnalysisElement(tag?)` |
| [`<score-rhythm-analysis>`](/score/element/analyze/score-rhythm-analysis/) | `defineRhythmAnalysisElement(tag?)` |
| — | `defineAllAnalysisElements()` registers all four. |

## View

Four View elements group representations by the data and resources they
use.

| Element | Representations | Register |
| --- | --- | --- |
| [`<score-view>`](/score/element/view/score-view/) | Read-only `piano-roll`, `staff` and `waterfall` over a whole Score. | `defineScoreViewElement(tag?)` |
| [`<score-grid-view>`](/score/element/view/score-grid-view/) | DAW-style piano-roll grid; edits a borrowed editor with a switchable toolbar. | `defineScoreGridViewElement(tag?)` |
| [`<score-pitch-view>`](/score/element/view/score-pitch-view/) | `keyboard`, `staff` and `fretboard` for currently held MIDI pitches. | `definePitchViewElement(tag?)` |
| [`<score-sheet-view>`](/score/element/view/score-sheet-view/) | Engraved sheet music in pages or a continuous column, editable like a notation program. | `defineSheetViewElement(tag?)` |

`defineAllViewElements()` from `@webmusic/score/view/element` registers all four.
Each type stays on its owning page, with its controls in external Parameters.
`score-view`, `score-grid-view` and `score-sheet-view` borrow resolved score data and position;
`score-pitch-view` borrows held notes. Each connects to an enclosing player or Rack part by
containment, or to the player named by `input`.

Editing is part of View. Load an editor with
[`loadScoreEditor`](/score/headless/view/score-editor/#load-from-a-url) (or create
one with `createScoreEditor`) and assign it to the `.editor` property of a player
or view; there is no `editor` attribute. Your application owns and disposes the
editor; borrowers release their subscriptions. Note editing belongs to
[`<score-grid-view>`](/score/element/view/score-grid-view/);
[`<score-view>`](/score/element/view/score-view/#follow-an-editor) follows an
editor read-only.

```html
<score-player id="p" src="/mxl/Arabesque%20No.1.mxl"></score-player>
<score-view type="staff" input="#p"></score-view>
<score-view type="waterfall" input="#p"></score-view>
<score-pitch-view type="keyboard" input="#p" low="48" high="84"></score-pitch-view>
```

No follower creates another player. Each component can be placed or omitted
independently; a tag-owned demo contains one player and that page's component.
See the [View API](/score/api/view/) and [Headless models](/score/headless/#view)
for application-owned presentation and the same data projections.

## Theming

Set public CSS custom properties on an element, its ancestor, or `:root`. They
inherit into Score's UIKit presenters, including controls inside Shadow DOM.
The default palette is mostly neutral with square corners; active notes keep
their role-specific accent defaults, and recording uses the shared
`--wm-recording` colour. Pressed icon buttons invert to `--wm-foreground` with
`--wm-accent-foreground` content.

```css
/* Apply to a shared wrapper, or put these declarations on one component. */
.music {
  --wm-component-background: transparent;
  --wm-component-border: 1px solid #8291a5;
  --wm-component-radius: 12px;
  --wm-foreground: #25344a;
  --wm-foreground-muted: #596b83;
  --wm-accent: #e23b3b;
  --wm-accent-foreground: #fff;
  --wm-border: #8291a5;
  --wm-control-border: #8291a5;
  --wm-control-radius: 6px;
  --wm-focus: #146dcc;
  --wm-focus-ring: 2px solid #146dcc;
}
```

`--wm-component-*` styles the outer surface. The border value is a complete CSS
border such as `1px solid #8291a5` or `none`; `--wm-border` and
`--wm-control-border` are colors. `--wm-component-padding` accepts CSS spacing.
`--wm-focus-ring` is a complete outline declaration used by icon buttons and
other controls that draw focus inside their edge; `--wm-focus` is the colour
that older focus outlines still read.
Presenter-specific `--wm-<presenter>-surface-*` values take precedence when a
surface needs its own background, border, radius or padding.

Inner drawing surfaces and controls have separate tokens. For example, making
the outer frame transparent does not erase the contrast between white and black
piano keys. For a completely transparent drawing surface, also set the relevant
`--wm-surface`, `--wm-surface-muted`, `--wm-surface-inverse`, or the specific
background token listed by its owner. Pair dark surfaces with readable
`--wm-foreground`, `--wm-foreground-muted` and `--wm-foreground-on-inverse`.
Keep `--wm-accent-foreground` visible against the accent color; it is independent
of the component background.

| Surface | Owning styling reference |
| --- | --- |
| Transport and compatibility alias | [Score player](/score/element/play/score-player/) |
| Piano/grid/chord input and recorder | [Note input](/score/element/play/score-note-input/) |
| Channel mixer | [Rack control](/score/element/play/score-rack-control/) |
| Parameters, envelope, EQ, LFO and macros | [Synth panel](/score/element/play/score-synth-panel/) |
| Score drawings and active notes | [Score view](/score/element/view/score-view/) |
| Piano-roll grid and editing toolbar | [Score grid view](/score/element/view/score-grid-view/) |
| Keyboard, staff and fretboard readouts | [Pitch view](/score/element/view/score-pitch-view/) |
| Engraved paper and ink | [Sheet view](/score/element/view/score-sheet-view/) |
| Live analysis | Each [Analyze component](#analyze) and its UIKit Harmony/Workbench tokens |

Existing legacy variables and explicit renderer color options retain their
documented precedence. CSS changes update DOM/SVG colors without replacing the
score or player. CSS cannot override an explicit renderer
color option that takes precedence over the theme.

Use `::part(...)` for the documented parts of Shadow DOM components such as
`score-note-input` and `score-synth-panel`. Score player, Analyze and View render in light
DOM: target their public `[part~="..."]` hooks instead. Do not select private
UIKit child classes. UIKit can also be mounted directly with the same variables,
parts and named handle nodes; see [UIKit styling](/uikit/).
`score-rack-part` is a nonvisual declaration. Demo wrapper elements inherit their
theme into the components they compose.
