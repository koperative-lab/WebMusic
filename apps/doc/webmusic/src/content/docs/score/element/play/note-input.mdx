**`<note-input>`** is the discrete-note performance surface. Set `layout` to pick the rendering and interaction model; all layouts share multi-touch, drag glissando, per-note reference counting, and the same output contract (`webscore:noteon` / `webscore:noteoff` + `.onNote`). Every layout also accepts the boolean `keyboard` attribute for QWERTY musical typing (see **Keyboard** below).

Its implementation keeps mapping rules and layout templates separate from DOM lifecycle and held-note interaction state, while the public element API remains unchanged.

## Live demo

The three layouts now share one live `<note-input>`. Change **layout** in Parameters to move between Piano, Grid and Chords without leaving the demo; the remaining rows always edit that same element. The Grid option starts with a playable pad map, while the Piano range and default chord set remain available when their layouts are selected.

The same Parameters panel can also **Mount [`<score-recorder>`](#score-recorder)**. It appears beside the input as an optional attached component, exposes its own `bpm` and `quantize` controls, and captures this surface through `.source`. Removing it returns the demo to note input alone; **Reset** restores the initial layout, parameters and attachment state.

## Piano

An on-screen piano keyboard. Hold and drag across keys to glissando. Set `start` and `end` to choose its MIDI range.

## Grid

A **10×3 Launchpad** laid out like the physical keyboard — **Q–P**, **A–;**, **Z–/** — for triggering samples or a percussion SoundFont. Map cells with the `map` attribute (`z1=35,a1=50,…`) or assign `.pads` (`{ midi, label? }` per cell, bottom-left = index `0`); only mapped cells are playable — the rest render dimmed and ignore pointer input. Row letters are **`q`** (top), **`a`** (middle), **`z`** (bottom); columns **`1`–`10`** left to right. Add `keyboard` for QWERTY musical typing.

## Chords

Buttons that each trigger a **whole chord** — diatonic triads of C major by default; override with `.chords`. Notes shared between held chords are reference-counted, so overlapping presses don't cut each other off.

## Keyboard

Add the boolean `keyboard` attribute on **any** layout — Piano, Grid, or Chords — for QWERTY **musical typing**: click **▸ Click to start** to focus the surface, then `A S D F …` play white keys, `W E T Y …` black keys, **Z** / **X** shift the octave, and **Esc** blurs. Blurring releases every held note and stops listening. Enable it in the same live demo by entering a value in the **keyboard** row; clear the field to turn it off.

<details class="component-section">
<summary>API</summary>


```ts
import { InteractivePlayer, Sound } from '@webmusic/score/play/headless';
import type { NoteInputElement } from '@webmusic/score/play/element';

const player = new InteractivePlayer();
player.addVoice('kbd', Sound.oscillator({ type: 'triangle' }));

const el = document.querySelector<NoteInputElement>('note-input')!;
el.setAttribute('map', 'a1=35,a2=36,z3=42'); // or el.pads = [{ midi: 35, label: 'BD' }, …]
el.onNote = (midi, velocity, on) => {
  if (on) player.noteOn('kbd', midi, velocity, 3600); // sustain until release
  else player.noteOff('kbd', midi);
};
```

| Member | Kind | Description |
| --- | --- | --- |
| `layout` | attribute / property | `piano` (default) / `grid` / `chords`. Switching at runtime releases held notes first. |
| `keyboard` | attribute | Boolean — adds QWERTY musical typing on any layout (`piano`, `grid`, `chords`). |
| `start` / `end` | attribute | MIDI range (piano without `keyboard`: `48`–`71`; with `keyboard`, the visible keys span the QWERTY row from `start` and shift with Z / X). Grid uses `map` / `.pads` only — `start` applies only with `keyboard` (octave anchor, default `48`). |
| `map` | attribute / property | Compact grid map for `layout="grid"` — comma-separated `ref=midi` pairs such as `a1=35,z2=42` (`q` / `a` / `z` row, column `1`–`10`). Unmapped cells stay idle. Ignored when `.pads` is set. |
| `velocity` | attribute | Velocity for triggered notes, 1–127 (default `100`; grid `110`). |
| `row-interval` | attribute | Used by the exported `gridCellMidi` helper for custom isomorphic UIs (not the built-in `grid` layout). |
| `.pads` | property | Override the grid pad map — `{ midi, label? }[]` (layout `grid`). Bottom-left = index `0`; only cells with `midi` play (blank / idle pads). Takes precedence over `map`. |
| `.chords` | property | Override the chord set — `{ label, notes }[]` (layout `chords`). |
| `.onNote(midi, velocity, on)` | property | Callback fired on every press (`on=true`) and release (`on=false`). |
| `.releaseHeld()` | method | Release every held note (pointer, chord, and QWERTY holds). |
| `webscore:noteon` / `webscore:noteoff` | event | Bubbling `CustomEvent`s with `detail = { midi, velocity }`. |

Disconnecting or changing layout releases held notes and removes the old
presenter's input listeners. Events and `.onNote` callbacks preserve attack
before release even when a listener synchronously removes the element or
changes its layout. Each callback receives the velocity captured for the same
event; changing `velocity` during event delivery does not change that callback's
payload. Reconnecting mounts fresh interaction state with no held notes.

</details>

<details class="component-section">
<summary>Styling</summary>

The host follows its available width and respects native `hidden`. Piano and grid layouts keep
readable key sizes in an internal horizontal viewport; chord buttons wrap into rows. In
`keyboard` mode, Left/Right scroll that viewport without releasing held notes. Without it,
focus the viewport for native keyboard scrolling. Changing container width does not remount
the surface.

The element uses the [UIKit Note tokens and parts](/uikit/notes/note/), including
`--wm-note-key-min-width` (default `2.25rem`), `--wm-note-cell-min-width` (default `2.5rem`),
and `::part(viewport)`. Inherited `--wm-note-*` and shared theme tokens remain available;
explicit legacy `--note-input-*` values below take precedence over their UIKit equivalents.

For a transparent frame with rounded keys, set `--wm-component-background: transparent`,
`--wm-component-radius: 12px` and `--wm-control-radius: 6px` on the element or its ancestor.
Key fills resolve through `--wm-note-key` / `--wm-surface` and
`--wm-note-key-alt` / `--wm-surface-inverse`; held notes use `--wm-note-active` /
`--wm-accent`, with independent `--wm-note-label-active` / `--wm-accent-foreground`.
These variables remain live when the layout changes.

After the explicit legacy border override, neutral key and pad outlines resolve through
`--wm-note-border` → `--wm-control-border` → `--wm-border` → `#d8d8d8`. Black piano keys retain their separate
`--wm-note-key-alt-border` outline.

```css
note-input {
  --note-input-bg: #fff;
  --note-input-surface: #f3f3f3;       /* grid cells */
  --note-input-key: #fff;              /* white keys */
  --note-input-key-alt: #222;          /* black keys / chord buttons */
  --note-input-active: #444;           /* held highlight */
  --note-input-border: #d8d8d8;
  --note-input-height: 120px;          /* piano height */
  --note-input-cell-height: 42px;      /* grid / chords */
  --note-input-gap: 0.4rem;
  --note-input-radius: 0;
  --note-input-focus: #444;           /* keyboard-mode focus ring */
  --note-input-overlay: rgba(255, 255, 255, 0.82); /* keyboard click-to-start veil */
  --note-input-accent: #111;           /* keyboard start button */
  --note-input-accent-color: #fff;
}
```

## `<score-recorder>`

Recording and input are separate elements in one workflow: `<note-input>` produces note events, and
`<score-recorder>` captures them into a `Score` that it can replay and export as MIDI or MusicXML.
Use **Mount recorder** in the live demo above to add this exact composition, edit its `bpm` and
`quantize` parameters, record a take, then remove it again without replacing the input.

Keep the two visible components as **siblings** and assign the input as the recorder's `.source`.
The recorder listens to the input's bubbling `webscore:noteon` / `webscore:noteoff` events while
armed without taking over the input's own `.onNote` sound callback. Its Shadow DOM does not project a
light-DOM input surface, so nesting `<note-input>` inside `<score-recorder>` is not the visible
composition shown here. If the recorder should also provide live monitoring, forward `.onNote` to
`recorder.input(midi, velocity, on)` instead.

**Stop** notates the captured notes through `notesToScore`, stores the completed `.take`, fires
`webscore:recorded`, and enables playback and export. Deterministic note capture and notation stay
separate from browser download and view rendering; the element is the public coordinator for those
pieces.

Use one feed path for each input: `.input()` monitors and records, while event
subscriptions only record. Overlapping presses of the same MIDI pitch pair
with releases in attack order. A single event reaching both the recorder and
its assigned source is captured once. Stop retains completed notes and
discards presses that have not received a release.

Changing `.source` discards unmatched presses so a release from the new source
cannot complete an old press; completed notes and the recording time origin
remain. Disconnect cancels the active take and removes input subscriptions.
The assigned source and last completed take remain available after reconnect;
call `.record()` to start a new take.

Sources, supplied sounds and supplied AudioContexts are borrowed. Disconnect
releases the recorder's monitoring/playback routes and owned resources without
disposing those supplied objects. Live monitoring and take playback alternate
ownership of the recorder's route to a supplied sound.

### Import and wiring

```html
<script type="module">
  import { defineNoteInputElement, defineScoreRecorderElement } from '@webmusic/score/play/element';
  defineNoteInputElement();
  defineScoreRecorderElement();
</script>

<note-input layout="piano" start="48" end="71"></note-input>
<score-recorder bpm="120" quantize="0.25"></score-recorder>
```

```ts
const keyboard = document.querySelector('note-input');
const recorder = document.querySelector('score-recorder');
recorder.source = keyboard;
```

<details class="component-section">
<summary>Recorder API</summary>

| Member | Kind | Description |
| --- | --- | --- |
| `bpm` | attribute / property | Tempo the take is notated against (default `120`). |
| `quantize` | attribute / property | Snap grid in quarters (for example `0.25` = sixteenths); `0` keeps faithful timing. |
| `.input(midi, velocity, on)` | method | Feed a note in — sounds it live and, while armed, times it. |
| `.record()` / `.stop()` | method | Arm the recorder / stop and notate; `stop()` returns the `Score`. |
| `.source` | property | Borrowed `EventTarget` whose note events feed recording while connected. Assignment survives reconnect; replacement discards unmatched presses. Use it to attach a sibling `<note-input>`. |
| `.sound` | property | Override the live-monitor and playback timbre. |
| `.audioContext` | property | Share an `AudioContext` with the live synth and playback. |
| `.player` | property (get) | The internal `InteractivePlayer` monitoring `.input()` notes. |
| `.take` | property (get) | The last completed take as a notated `Score`, if any. |
| `.recordingActive` | property (get) | `true` while armed. |
| `webscore:recorded` | event | Bubbling `CustomEvent` with `detail = { score }` after a successful stop. |
| `webscore:error` | event | Bubbling, composed `CustomEvent` with `{operation: 'play', error}` when take playback or a presenter playback command fails. |

The **Record** button arms or stops capture, **Play** auditions the completed take, and **MIDI** /
**MusicXML** download it through `serializeMIDI` / `serializeMusicXML`.

</details>

<details class="component-section">
<summary>Recorder styling</summary>

The host follows its available width and respects native `hidden`. The
[UIKit Recorder](/uikit/mixing-capture/recorder/) wraps controls and export buttons within
that width, while long status text breaks across lines. Resizing does not change the take or
playback state. Use its public `--wm-recorder-*` tokens and `::part(exports)`; inherited shared
theme tokens remain available. Explicit legacy `--rec-*` values take precedence over their
UIKit equivalents.

`--wm-component-background`, `--wm-component-border` and `--wm-component-radius`
style the outer frame; `--wm-control-radius` styles the buttons. The recording
accent falls back from `--wm-recorder-accent` to `--wm-accent` and then red;
its text falls back to `--wm-accent-foreground`, so a transparent background
does not make the armed label transparent.

```css
score-recorder {
  --rec-border: #d8d8d8;
  --rec-btn-border: #d8d8d8; /* idle button outline */
  --rec-rec: #c0392b;        /* armed Record button */
  --rec-text: #222;          /* control text */
  --rec-radius: 0;
}
```

</details>
