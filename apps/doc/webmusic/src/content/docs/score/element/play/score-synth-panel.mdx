`<score-synth-panel>` is a composable control surface for an instrument or effect.
In module scope it borrows the target's shared parameters, ADSR, native LFO and
macro controllers. Outside module scope, its standalone compatibility mode
accepts descriptors and callbacks, then connects its optional
effects / EQ bus to the audio graph you already own. This keeps the panel reusable with
`OscillatorSynth`, a worklet, a sampler, or an application-specific engine.

The Element composes published UIKit section-panel, parameter-rack, envelope, EQ, LFO and
macro presenters. Parameter descriptors, `LfoController`, `EqController` and the DOM-free
[`SynthPanelAudioGraph`](/score/headless/play/sound/#synth-backends-synthpanelaudiograph) own the
behavior behind those controls. The panel borrows its AudioContext and target callbacks;
it creates no player or synth voice.

The demo nests a piano `<score-note-input>` and the panel inside a `<score-player>` that loads
Arabesque No. 1. Nested, both find the player's instrument through the module context: play the
keyboard or the piece, and the **sound** and **envelope** sections edit that instrument live.

## Import

```html
<script type="module">
  import { defineSynthPanelElement } from '@webmusic/score/play/element';
  defineSynthPanelElement();
</script>
<score-synth-panel sections="sound,effects,envelope,eq,lfo,macros"></score-synth-panel>
```

## Ports and composition

`<score-synth-panel>` is a control surface for a module, not a module itself:
it declares no ports, provides no module context and takes no part in Session
timing. In attached mode it edits the borrowed module's `control` parameters,
insert chain and envelope handles in place. Resolution runs:

1. `mode="insert"`, which forces the standalone panel graph;
2. `.moduleTarget`, an explicit `ModuleHandle` (`null` unbinds);
3. `target="#id"`, such as a player or a realized `<score-effect>`;
4. containment: the nearest module context's target — a player's synth and
   inserts, or a Rack's master;
5. outside any module scope, the standalone panel.

An explicit or contained target that has not resolved reports
`.bindingState === 'unresolved'` and never builds a fallback graph. See
[Attach to an existing module](#attach-to-an-existing-module) for the section
behavior.

```html
<score-player src="/midi/Arabesque%20No.1.mid">
  <score-note-input layout="piano" start="48" end="71"></score-note-input>
  <score-synth-panel sections="sound,envelope"></score-synth-panel>
</score-player>
```

## Sections

The `sections` attribute is an ordered comma list. One element can show only the
controls a view needs. In standalone mode, assign the following properties;
attached mode resolves the target's capabilities as described below.

| Section | Assign | What appears |
| --- | --- | --- |
| `sound` | `.sound` / `.params` | Grouped rotary parameters whose `apply(value)` callbacks drive your synth. |
| `effects` | `.context` + `.effects` | Live parameters from an ordered array of `Effect` recipes. |
| `envelope` | `.envelope`, `.ranges`, `.apply` | An accessible draggable ADSR curve. |
| `eq` | `.context` + `.bands` | A draggable frequency-response editor and three-band Web Audio graph. |
| `lfo` | `.lfo` + `.target` | Shape, rate, depth, phase and run controls for a borrowed modulation target. |
| `macros` | `.macros` | Knobs that map one normalized value onto several targets. |

The other sections are configured from JavaScript, as the property table below describes:
`.sound` replaces the sound descriptor array, `.bands` rebuilds the equalizer, `.effects` assigns real
`Effect[]` entries whose parameters the effects section then exposes, and the LFO and macro
properties configure modulation. `sections` orders or hides modules.

When both `effects` and `eq` are active their audio is spliced into one serial chain (effects → eq)
behind the shared `.input` / `.output`.

Unconfigured sound and macro sections, and effects/EQ sections without their required
graph configuration, show the shared outlined-square waiting animation. Assigning their
properties replaces the indicator with the configured controls. Envelope and LFO editors
remain immediately usable with their defaults; they do not wait for sound or a held note.
Status descriptions remain available to assistive technology, and reduced motion uses a
static square.

## Section state and lifetime

In standalone mode, changing `sections` re-renders the visible presenters while preserving sound values, ADSR, EQ bands,
effect parameters and macro positions. A running LFO also remains active when its section is hidden;
showing it again restores the same shape, rate, depth and phase. Disconnecting the whole element
tears down its audio nodes and LFO loop. Reconnecting creates a fresh stopped controller with the
retained modulation settings.

The standalone panel borrows `.context`, `.target`, descriptor callbacks and every object they close over. It
never disposes your synth or target. It owns only the Web Audio nodes and UI presenters that it
creates from those assignments.

## Standalone audio routing

Assigning `.context` creates stable `.input` and `.output` boundary nodes. Route a synth into the
input once and the output to a destination once. Changing `.effects`, `.bands`, or `sections` only
replaces the internal path; it does not invalidate those external connections. When neither effects
nor EQ is active, the boundaries are connected by a dry bypass.

```js
panel.context = context;
synth.connect(panel.input);
panel.output.connect(context.destination);

panel.effects = [Effect.reverb(), Effect.delay()];
// The two external connections above are still valid.
```

Effects run before EQ. Hiding `effects` or `eq` removes that module from the signal path while
retaining its configuration for a later render.

## Audio routing and parameter updates

Connect a source to `.input` and `.output` to your destination after configuring a context.
These ports keep their identity within the same
AudioContext as effects, EQ bands or their sections change. The panel builds and connects
the candidate DSP before retiring the old chain; a construction or connection failure
releases completed candidate resources and leaves the last usable chain in place.

With no applicable effects/EQ, the same ports carry a dry bypass from input to output.
Re-enabling DSP replaces that internal path and retains the external connections. Replacing or
clearing `.context`, or disconnecting the panel, releases its ports; reconnect your routing
after a new context or mounted lifetime. The panel never closes the borrowed context.

Sound parameter callbacks may finish asynchronously. The control shows the requested value
while `apply(value)` runs. A failed current request restores the preceding displayed value;
an older failure cannot overwrite a newer request, replacement descriptors or a new mounted
lifetime. Failures from a still-mounted control reach `webscore:error`; obsolete presenter
rejections are contained after replacement or disconnect. The panel cannot undo side effects
inside an application-supplied callback.

## Attach to an existing module

`target="#effect"` selects a module or realized effect instance; `.moduleTarget`
accepts an object with higher precedence. Set that property to `null` to unbind,
or `undefined` to resume selector/context lookup. Without an explicit selector,
a panel in module scope borrows the nearest target. An unresolved explicit target
stays unresolved and never creates a fallback audio graph.

Attached `sound`/`effects` sections edit the target's exact `ParamHandle`s. Two
panels share the same values and instance. Changing sections, hiding or removing
a panel does not rebuild or dispose that target. `.module` exposes the selected
handle and `.bindingState` is `standalone`, `unresolved` or `ready`; `input` and
`output` are undefined in attached mode.

`mode="insert"` explicitly selects the legacy standalone panel graph. Outside
module scope with no target, legacy behavior remains the default. The existing
`.target` **property** remains an LFO target; the new module object property is
`.moduleTarget`, while HTML `target` is the selector.

The attached envelope section uses the target's `attackSeconds`, `decaySeconds`,
`sustainLevel` and `releaseSeconds` handles. Native Sound voices capture all four
stages at onset; edits affect new notes. A target without these handles shows
the unavailable capability. Attached EQ remains unavailable unless supplied by
the target's effect parameters.

### Attached LFO and macros

`lfo-parameter="cutoff"` or `.lfoParameter = 'cutoff'` selects a shared parameter
id; the default prefers `detune`, then the first audio-rate parameter.
The Amount control or `.lfoAmount` sets the maximum additive excursion in its
native unit, independently of its legal/display range. `.lfo.depth`
scales that amount from 0 to 1, while `.lfo.rate` is Hz. Starting the LFO explicitly
prepares the target if needed. Merely displaying the section creates no audio
graph. Unsupported precision is shown as unavailable.
An explicit start also prepares a target whose lazy instrument has not yet
exposed its parameters. Stopping before preparation completes cancels that
pending start.

Changing the selected parameter cancels its pending preparation-time run intent
and settings. A late completion cannot start modulation on the new selection or
on a replacement handle with the same id. Already running parameter-owned LFOs
retain their own state when the panel displays another parameter.
Configuration queued before a target exposes parameters belongs to that module
and connected lifetime. Replacing the target or removing the panel revokes it;
the same module can still apply it when ready. Explicit configuration before the
first mount, or a new assignment while detached, belongs to the next binding.

Parameter ids for LFO and `.parameterMacros` resolve only in the selected
module's `params`. They do not search its insert slots or manufacture namespaced
aliases. To modulate an effect, target that effect's handle directly. A realized
effect handle without an output/insert context also needs the borrowed
`.context` for its native LFO; macros need only the parameter handles. Headless
callers can connect a control signal directly through the effect's `ParamHandle`.

The native LFO belongs to the parameter/context, so two panels edit the same
controller. Hiding the section or removing either panel leaves it running.
Releasing the target's audio context stops it; a later context needs an explicit
restart. The phase readout is an audio-clock estimate; assigning phase in attached
mode reports `webscore:error` because phase restoration across seek/loop is not supported.

`.parameterMacros` accepts `{id, label?, value?, targets}` with targets
`{parameter, min, max}` in each parameter's native unit. Panels with the same
surface and macro id share one controller. The first definition establishes that
id's mappings; a later conflicting definition reports `webscore:error`. Explicit initial `value`
writes targets when that controller is first created. Subsequent direct parameter
edits do not infer a new macro position.

Base knobs and macro writes replace pending base automation for the handles they
edit. LFO remains an independent additive mapping. A dashed outer arc and an
accessible description show the predicted modulation range; neither claims a
measurement of the effective audio-rate value. See [the sound and modulation
example](/bridge/modular-composition/#sound-and-modulation) and the
[Headless controllers](/score/headless/play/sound/#shared-parameter-controllers).

<summary>API</summary>


```ts
const WAVES = ['sine', 'square', 'sawtooth', 'triangle'];
const panel = document.querySelector('score-synth-panel');

// "sound": one knob per descriptor; `group` clusters them in labelled blocks
panel.sound = [
  { group: 'osc', name: 'wave', value: 3, min: 0, max: 3, options: WAVES, apply: (i) => synth.setParam('type', WAVES[i]) },
  { group: 'osc', name: 'tune', value: 0, min: -50, max: 50, step: 1, unit: '¢', apply: (v) => synth.setParam('detune', v) },
  { group: 'filter', name: 'cutoff', value: 8000, min: 200, max: 12000, step: 10, unit: 'Hz', apply: (v) => synth.setParam('cutoff', v) },
];

// "effects" + "eq": build the chain on a context, splice .input/.output into the graph
panel.context = ctx;
panel.effects = [Effect.filter(), Effect.delay(), Effect.reverb()];
panel.output.connect(ctx.destination);
player.destination = panel.input;

// "envelope": wire the ADSR editor to the synth
panel.apply = (e) => {
  synth.setParam('attackSeconds', e.attack);
  synth.setParam('decaySeconds', e.decay);
  synth.setParam('sustainLevel', e.sustain);
  synth.setParam('releaseSeconds', e.release);
};

// "lfo" + "macros"
panel.lfo = { shape: 'sine', rate: 1, depth: 0.6, phase: 0, running: false };
panel.target = { min: 300, max: 9000, unit: 'Hz', apply: (v) => synth.setParam('cutoff', v) };
panel.macros = [{ label: 'OPEN', targets: [
  { name: 'cutoff', min: 600, max: 11000, apply: (v) => synth.setParam('cutoff', v) },
  { name: 'level', min: 0.06, max: 0.22, apply: (v) => synth.setParam('gain', v) },
] }];
```

| Member | Kind | Description |
| --- | --- | --- |
| `sections` | attribute / property | Comma list of `sound` / `effects` / `envelope` / `eq` / `lfo` / `macros` (default `sound,effects`). Toggling re-renders; current values survive. |
| `target` / `.moduleTarget` | attribute / property | Selector or object selecting a borrowed module. Object wins; `null` unbinds and `undefined` resumes lookup. |
| `mode` | attribute | `insert` forces standalone effects/EQ ownership; otherwise auto-select attached or standalone behavior. |
| `.module` / `.bindingState` | property (get) | Selected borrowed handle and `standalone`, `unresolved` or `ready` state. |
| `lfo-parameter` / `.lfoParameter` | attribute / property | Shared parameter id for attached native modulation. |
| `.lfoAmount` | property | Nonnegative maximum excursion in the attached target's native units; default `1`. The attached Amount control edits the same shared state. |
| `.parameterMacros` | property | Shared id-based `ParameterMacroConfig[]`; distinct from standalone callback `.macros`. |
| `.sound` (alias `.params`) | property | Standalone `{ name, value, min, max, step?, unit?, options?, group?, apply }[]` — one knob each; `apply(value)` fires live and may return a promise. Failed current writes restore the prior displayed value without overwriting newer writes. Attached sound controls use the target's handles. |
| `.context` | property | Borrowed `AudioContext` for the standalone effects / EQ chain. In attached mode it is a fallback for an explicit target without a prepared port/insert context. |
| `.effects` (alias `.effect`) | property | `Effect[]` to chain and expose as knobs. |
| `.input` / `.output` | property (get) | Stable standalone entry / exit `AudioNode`s for the current `.context`; undefined when attached. The effects → EQ path can rebuild without changing identity; an empty path is dry. |
| `.envelope` | property | Get / set standalone ADSR (`{ attack, decay, sustain, release }`). Attached controls edit the target handles directly. |
| `.ranges` | property | Get / set per-stage envelope maxima in seconds (`{ attackMax, decayMax, releaseMax }`, default `2`). A live assignment repaints the graph. |
| `.apply(env)` | property | Standalone callback for envelope edits. |
| `.bands` | property | EQ bands `{ frequency, gain?, q? }[]` (default low / mid / high). |
| `.lfo` | property | Get / set `{ shape, rate, depth, phase, running }`. Attached native mode shares state and rejects phase assignment through `webscore:error`; standalone mode retains its callback controller. |
| `.target` | property | Standalone borrowed LFO destination `{ min, max, value?, unit?, apply(value) }`. Assignment never applies eagerly; the panel never destroys it. |
| `.macros` | property | Standalone `{ label?, value?, targets }[]` — each macro knob maps `0..1` into callback targets. Attached mode uses `.parameterMacros`. |
| `webscore:envelope` | event | `detail = { attack, decay, sustain, release }`. |
| `webscore:macro` | event | `detail = { index, label, value }`. |
| `webscore:lfo` | event | Full `.lfo` snapshot after a shape / rate / depth / running control change. Animation-frame phase changes and phase-only assignments do not emit an event. |
| `webscore:error` | event | Bubbling, composed error boundary for presenter, sound-parameter callback, envelope and LFO failures. `SynthPanelEnvelopeErrorDetail` and `SynthPanelLfoErrorDetail` contain `{ operation: 'synth-panel', error }`. Direct audio-configuration property assignments can throw construction or connection errors. |

<details class="component-section">
<summary>Styling</summary>

The host fills its container and can shrink inside flex/grid layouts; the native `hidden`
attribute hides it. The panel draws the component's one outer frame, a 1px hairline in the line
colour (`--wm-control-border`, then `--wm-border`, then `light-dark(#d8d8d8, #333)`), with no outer
padding. Sections carry their own `.6rem` inset and are divided by hairlines; parameter groups,
macro items and the EQ, envelope and LFO presenters mounted inside leave their own frames to the
panel. Parameter groups and macro readouts wrap; envelope and EQ values occupy rows below their
plots. The plot-height tokens control the SVG only, so the component grows to include its readouts.

Plots share the panel surface: the envelope, EQ and LFO graphs default to `--wm-surface` with
`--wm-foreground` ink, and the LFO phase head is ink. Readouts below the plots use
`--wm-foreground-muted`. To invert the graphs, set `--wm-envelope-background`, `--wm-eq-background`
and `--wm-lfo-wave-background` with their curve tokens, or the legacy `--synth-graph-bg` and
`--synth-graph` overrides together. Use `--wm-component-background`, `--wm-component-border` and
`--wm-component-radius` for the panel surface, and `--wm-control-radius` for controls. Specific
presenter tokens and legacy overrides remain available for independent sections.

```css
score-synth-panel {
  --wm-parameter-size: 3rem;                       /* knob diameter */
  --wm-parameter-track: light-dark(#dcdcdc, #333); /* knob arc */
  --wm-parameter-pointer: light-dark(#111, #eee);  /* pointer */
  /* Optional: invert the envelope, EQ and LFO graphs */
  --synth-graph-bg: light-dark(#111, #eee);
  --synth-graph: light-dark(#fff, #111);
  --synth-graph-grid: light-dark(#333, #ccc);
  --synth-graph-fill: light-dark(#222, #ddd);
  --synth-accent: light-dark(#fff, #111);          /* LFO phase head */
  --synth-radius: 0;
}
```

Waiting sections expose `synth-status`, `synth-status-indicator` and `synth-status-message` parts and inherit the shared `--wm-status-*` tokens.

The shared envelope and LFO sections expose the same stable parts as their standalone presenters.
Envelope exposes `root`, `svg`, `grid`, `area`, `curve`, `handle`, `readout`, `inputs` and `input`;
LFO exposes `root`, `row`, `run`, `shapes`, `shape`, `control`, `label`, `rate-control`,
`depth-control`, `input`, `rate`, `depth`, `value`, `rate-value`, `depth-value`, `wave`, `curve` and
`head`.

For inner graphs and controls, explicit `--synth-*` values retain precedence
where they map onto the shared presenters. Outer boxes first read their
`--wm-*-surface-*` and `--wm-component-*` values, then their legacy fallback.
The Element supplies no default legacy values: without an explicit override, the relevant
`--wm-panel-*`, `--wm-envelope-*`, `--wm-eq-*` and `--wm-lfo-*` tokens apply, followed by
their shared UIKit tokens and built-in fallbacks. Parameter and macro controls use their
`--wm-parameter-*` and `--wm-macro-*` tokens directly; inside the panel, the parameter rack, macro
rack, envelope and EQ boxes read `--wm-parameter-surface-*`, `--wm-macro-rack-surface-*`,
`--wm-envelope-surface-*` and `--wm-eq-surface-*` (padding, border, radius, background), which
default to no frame. Section and macro-item dividers use `--synth-box-border`, then the line
colour. Panel border, padding and section gap can be set with `--wm-panel-border`,
`--wm-panel-padding` and `--wm-panel-gap` (default `0`).
