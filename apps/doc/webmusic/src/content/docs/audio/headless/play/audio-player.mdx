`AudioPlayer` is the central Audio command surface. It retains one identity while
its clip changes, borrows an editing document, or delegates to an existing queue/mix backend. It creates no
second transport clock. Use [`AudioClipPlayer`](/audio/headless/play/audio-clip-player/)
when an immutable single-clip engine is all the application needs.

The demo constructs one nonvisual player and controls it with plain inputs. Load
the Arabesque No. 1 WAV, switch between a clip and a two-pass queue, or clear and reselect the
source. Its readouts follow the object's events; the demo owns decoding and queue
cleanup, while the facade owns its context and clip engine.

## Import

```ts
import {AudioPlayer, AudioPlaylist, AudioMixer} from '@webmusic/audio/play/headless';
import {loadClipFromUrl} from '@webmusic/audio/play';

const player = new AudioPlayer();
const clip = await loadClipFromUrl('/wav/Arabesque%20No.1.wav', {context: player.audioContext});
player.setClip(clip);
await player.play();
player.pause();

const queue = new AudioPlaylist({
  audioContext: player.audioContext, entries: [{id: 'take', clip}],
});
player.setTransport(queue); // borrow the queue without disposing it
await player.play();

const mix = new AudioMixer({audioContext: player.audioContext});
mix.add({id: 'stem', clip});
player.setTransport(mix.transport);
await player.play();

const dispose = () => {
  player.setTransport(undefined); // detach the borrowed backend
  queue.dispose();
  mix.dispose();
  player.dispose(); // release its owned context after the borrowers
};
```

## Ownership and source selection

`setClip` selects an owned low-level clip engine, stopped at zero. The engine is
created lazily. Replacing it releases only that owned engine, preserving facade
identity and its output tap/context. Assigning the same selected clip is a no-op.
`setTransport` selects a borrowed backend and preserves its state. Selecting a
new nonempty clip or transport pauses the previous backend first, preserving its
position and preventing hidden overlap. Clearing a connection only detaches it. The facade
never stops or disposes a borrowed backend merely because it is detached.

The backend supplies all position/state readback. A queue uses seconds within its
active entry and exposes that clip. A mix uses its group axis and has no single
clip or aggregate analyser. Unsupported analyser/clock/scratch capabilities are absent; unsupported live control setters throw rather than silently succeeding.
Sharing this facade does not complete shared-clock injection across mix members.

## Ports and composition

`player.module` is the facade's `ModuleHandle`: its `id`, `inserts`,
`prepare()` (which preloads), `subscribe`, `getPort(name)` and a `ports()`
enumeration, so
[`getModulePort(player.module, 'main', 'audio')`](/kernel/api/#module--webmusickernelmodule) resolves its output.

| Family | Port | Direction | Present |
| --- | --- | --- | --- |
| audio | `main` (alias `output`) | output | Once prepared, while it plays an owned clip or edited sequence; over a borrowed playlist or mixer, that group's own stable output (`peekOutputPort()`), observed and never rerouted |
| source | `source` | output | Always: `webmusic.audio-clip`, mirroring the selected clip and its loading and error state |
| transport | `transport` | output | When a `moduleContext` lends one |

With the `moduleContext` option the facade prepares its AudioContext from that
scope's audio environment, installs no default speaker route and never closes the
context. An editor document's sequence scheduler takes its lookahead ticks from
that environment's `createTickSource`, so an offline module render
([`renderModuleGraph`](/kernel/api/#module--webmusickernelmodule)) advances it
in rendered time. It does not register itself with a Session; its host does.
`<audio-player>` and Bridge's [`registerAudioParticipant`](/bridge/headless/score-audio-session/) register
it on `clip-seconds`, reporting `shared-anchor` when the buffer engine attaches
Session scheduling and `media-follower` otherwise; `<audio-player>` registers a
borrowed queue once on `queue-entry-seconds`.

## Shared Session scheduling

An owned buffer clip can borrow a Session scheduling binding through
`attachScheduling(binding)`. Register `preload` as participant preparation and
`activateScheduling` as activation: preparation never resumes audio, and activation
completes before the shared future origin is chosen. While attached, route all
transport changes to the Session. Direct clip transport commands throw and scratch
input is unavailable; local gain, pan and effects remain editable.

`timingCapabilities` is a resource-free declaration of the selected backend.
`schedulingMode` reports native continuous buffer looping, bounded lookahead with
silence outside a clip, or approximate media coordination. See the
[clip scheduling guarantees and limits](/audio/headless/play/audio-clip-player/#shared-session-scheduling)
for offsets, rates, suspension, effect tails and scheduling horizons. A borrowed
backend must explicitly provide scheduling support; an ordinary playlist or mixer
does not acquire these guarantees just by being attached to the facade.

Replacing an owned clip releases its scheduling lease and cancels its sources
without pausing or changing the borrowed Session. The stable facade output remains
available. The host must register the replacement clip to resume coordinated
playback; `<audio-player>` manages that registration for modular composition.
When the facade attaches a scheduling-capable borrowed backend, it owns only that
attachment lease. Replacing or disposing the facade releases the lease without
disposing the borrowed backend. A backend already attached independently retains
its caller-owned attachment when the facade detaches it.

## Realized effects and module output

`setEffect(recipe)` updates the legacy compatibility slot of the prepared
`insertChain`; explicit insert slots remain in place. `outputPort` exposes the
prepared stable output for leased replacement, sends and taps. These are lazy
resources: observing module capabilities does not prepare a graph.

The `AudioPlayer` facade exposes `.module` for capability discovery. Its
`insertChain` is available for its owned clip engine; a source-free or borrowed
backend does not invent a chain. Explicit preparation and ownership follow the
selected backend. Use [Kernel routing leases](/kernel/api/#module--webmusickernelmodule)
when admitting an output to a mixer or adding a side tap.
Readiness observers may start playback. Preparation retains that same engine,
so subsequent stop/dispose commands release its sources and timers. A source
replacement or disposal during readiness cancels the superseded preparation.

## Edited sequence playback

```ts
import {createAudioClipEditor} from '@webmusic/audio/view/headless';
import {AudioPlayer} from '@webmusic/audio/play/headless';
import {loadClipFromUrl} from '@webmusic/audio/play';

const clip = await loadClipFromUrl('/wav/Arabesque%20No.1.wav');
const editor = createAudioClipEditor(clip);
const player = new AudioPlayer();
player.setDocumentSource(editor);
await player.waitForDocumentRevision(editor.getSnapshot());
editor.transaction('Insert silence', (transaction) => transaction.add({
  type: 'insert-silence', frame: 0, length: clip.sampleRate, id: 'opening-silence',
}));
const result = await player.waitForDocumentRevision(editor.getSnapshot());
if (result.status === 'applied') await player.play();
player.dispose(); // releases playback leases; never disposes editor
editor.dispose();
```

The player owns a segment-aware transport behind its existing borrowed-transport
interface. Revisions preserve that transport and clock identity. Document
replacement, detachment and disposal release this owned transport, its scheduled
voices, cached chunks and asset leases. The editor and an injected context stay
caller-owned. `.clip` is undefined for a sequence; it never pretends the first
asset is the document. Read `.source.kind` to distinguish `empty`, `clip` and
`sequence`. Clip-only companions are unavailable; an editor-bound waveform reads
the sequence, and meters can follow the graph after explicit play/preload.

Applying an edit pauses playback, cancels scheduled work, validates and retains
sequence references, then publishes the exact applied document ID/revision.
A revision that sounds the same — equal format, length and segments with an
identity position map, such as a beat grid or marker edit — is applied in
place instead: playback keeps running, prepared chunks stay valid and the new
revision is published as applied with `positionPolicy: 'preserve-frame'`.
It reads no PCM and creates/resumes no AudioContext. Applied revisions stay
paused. `play()` during preparation or a failed application rejects with
`AudioDocumentApplicationError` code `not-ready`. A failure retains the last
applied snapshot and the edited document; retry explicitly. Same-source assignment
is a no-op. Detachment clears the sequence instead of restoring an earlier clip.
If releasing an obsolete attempt synchronously attaches another document, the
old disposal notification cannot clear the new request. Revision waits and
explicit retries continue to target the new attachment. Likewise, a detach,
replacement or clip/transport selection made by a `sourcechange` listener while
an attachment is being selected wins over that attachment.

Position maps compose across skipped revisions, failure and undo. Positions inside
deleted content collapse to the deletion boundary with left affinity; undo does
not reconstruct that lost position. Stop/seek during preparation override older
position intent. Missing map chains reset to zero and clear loops, reported as
`positionPolicy: 'reset-origin'`; valid maps report `preserve-frame`. Collapsed or
inverted mapped loop ranges are disabled. Rate, gain, pan and valid loops survive
adoption. Sequence seeks and loop bounds round to the nearest output frame;
loop ends also clamp to the sequence length. Scheduling and reported positions
use these same accepted bounds. An explicit `setLoop` that collapses after
rounding is rejected. A seek to the end of an unlooped sequence during playback
stops there and emits `end`; a later `play()` starts again from zero.

The configured loop (the `loop` option or the last accepted `setLoop`) is kept
separately from the mapped loop of the current document. Each new attachment,
and a clip selected after detachment, starts from the configured loop. Its range
is clamped to the first applied revision; a range that lies beyond that content
is disabled instead of failing the revision. A mapped or clamped loop that an edit
leaves too short to schedule within the 512-voice budget is likewise disabled,
while an explicit `setLoop` with such a range still throws.

Playback reads bounded chunks with segment gain, linear envelopes and silence
through the same Core range reader as explicit WAV rendering. The default chunk
is 16,384 frames; `preparedBytesLimit` defaults to 64 MiB across active and inactive
PCM chunks. Inactive chunks are evicted in least-recently-used order before allocation;
active chunks remain pinned. A chunk larger than the budget fails document
application. A running allocation that cannot fit fails playback and stops voices.
No revision stores a full rendered sequence. Scheduling uses a 200 ms lookahead,
25 ms timer and at most 512 scheduled voices. Every chunk a loop crosses needs its
own voice per pass, so a short loop that straddles a chunk boundary counts twice;
loops exceeding the budget are rejected before starting, and density is rechecked
on rate changes. Browser timer throttling can still interrupt live audio; this is
not a seamless background-rendering engine.
Sequence rate changes transpose; `setPreservesPitch(true)` is unsupported and
throws. Sequence scratch sessions are unavailable.

### Construction and selection

| Member | Contract |
| --- | --- |
| `new AudioPlayer(clip?, options?)` / `createAudioPlayer(clip?, options?)` | Empty by default. `AudioPlayerOptions` uses the [clip engine options](/audio/headless/play/audio-clip-player/): context/destination, engine, media adapter, rate, volume, pan, loop, pitch preservation and effects. Adds positive safe-integer `chunkFrames` (16,384) and `preparedBytesLimit` (67,108,864 bytes) for document sequences. |
| `setClip(clip \| undefined)` | Replace the selected source; undefined clears it. Source replacement invalidates the old owned playback and scratch work. While a document source is attached, a clip rejects with `source-conflict` and undefined detaches the document. |
| `setTransport(transport \| undefined)` | Borrow an `AudioPlayerTransport`; undefined detaches the selected borrowed backend. Direct and indirect facade borrowing cycles are rejected. While a document source is attached, a transport rejects with `source-conflict` and undefined detaches the document. |
| `clip` / `transport` | Readonly selected clip or selected transport; sequences and mixes return no clip. Document playback owns its transport even though this property exposes the borrowed facade path. |
| `source` | `AudioPlaybackSourceSnapshot`: `{kind: 'empty', clip: undefined, revision}`, `{kind: 'clip', clip, revision}`, or `{kind: 'sequence', clip: undefined, sequence, assets, documentId, documentRevision, revision}`. `revision` counts source publications, independently of the document revision. |
| `setDocumentSource(source \| undefined)` / `documentSource` | Borrow a Core `AudioDocumentSource`. Independent clip/transport conflicts reject before replacement. Undefined detaches and releases the owned sequence engine. Invalid `chunkFrames` or `preparedBytesLimit` options throw `RangeError` here, and a configured `preservesPitch: true` rejects the attachment because sequences do not support it; a later attempt with the same source retries. |
| `documentBinding` | `{status, attempt, requested?, applied?, positionPolicy?, documentCoordinates, error?}`. Status is `empty`, `preparing`, `ready` or `error`; requested/applied values are `{documentId, documentRevision}`. Coordinates are usable only when ready. |
| `waitForDocumentRevision(target)` | Observe the current requested revision; resolves `applied`, `superseded` or `failed`, with target and attempt. Unknown future revisions fail with `unknown-revision`; obsolete targets and detach/dispose resolve superseded. Applied confirms the exact target is active at settlement. |
| `retryDocumentApplication()` | New attempt for the current requested revision. Earlier failed results stay terminal; new waiters observe the retry. |

### Commands and state

| Member | Contract |
| --- | --- |
| `play(when?)` | Promise resolves after start/preparation, not at natural completion. `when` is absolute AudioContext seconds, supported according to the selected backend. Empty/disposed instances do nothing. |
| `pause()` / `stop()` | Delegate to the current backend. Pause retains position; stop resets according to that backend. |
| `seek(seconds)` / `seekFraction(fraction)` / `scrub(deltaSeconds)` | Delegate seeks on the selected content axis. Nonfinite `seconds` throw `RangeError` before any backend command or document position intent. A `NaN` fraction throws; other fractions, including `±Infinity`, clamp to 0–1. Scrub is a relative seek, not scratch audio. |
| `preload()` | Prepare the selected backend without starting sound, when supported. |
| `activateScheduling()` | Promise; resume the owned clip context or delegate the borrowed backend's explicit activation capability. Does not start a private clock. Unsupported backends throw. |
| `attachScheduling(binding)` | Return a ConnectionLease for shared Session scheduling. Delegate to the owned clip or an explicitly supporting borrowed backend; unsupported backends throw. |
| `setVolume(value)` / `setRate(value)` / `setPan(value)` | Set clip controls; rate clamps to 0.25–4, pan to −1–1, volume is nonnegative. Nonfinite input throws. A selected borrowed backend must expose the requested setter or the command throws without committing a new retained setting. |
| `setLoop(loop)` / `setPreservesPitch(value)` | Clip/sequence configuration. `setLoop` applies to the owned clip engine or document sequence and is never forwarded to a borrowed queue or mix: with one selected it throws without changing the configured loop, and attaching one does not replay it. Queue loop belongs to the queue's list policy; do not infer group loop/pan/pitch support. |
| `beginScratch()` / `scratching` | Borrow the selected backend's optional scratch session. See [scratch sessions](/audio/headless/play/audio-clip-player/#scratch-sessions). |
| `seconds` / `currentTime` / `duration` / `progress` | Live position, duration and fraction; zero for empty input. |
| `playing` | Selected backend's playback state. |
| `loading` / `loadError` | Selected borrowed backend's pending input and failure; false/undefined for an owned clip or a backend without readiness ports. Playlist prefetch is excluded unless it is the selected entry. |
| `volume` / `rate` / `pan` | Facade clip settings; `rate` reads the effective mapped Session rate for an attached owned clip. A backend can expose narrower control support. |
| `timingCapabilities` | PlaybackTimingCapabilities declaration without preparing audio; an undeclared external backend reports no shared-clock, future-start or native-loop guarantees. |
| `schedulingMode` | PlaybackSchedulingMode for the selected backend; see the clip scheduling reference. |
| `followsSession` | Whether the selected owned clip or explicitly declaring borrowed backend currently follows a Session scheduling binding. |
| `audioContext` | Lazily creates or returns the borrowed AudioContext for shared decoding/owned playback. Throws after disposal. A borrowed group may own a different context; sharing must be configured explicitly. |
| `clock` | Selected engine's optional read-only transport clock; the facade owns no clock. |
| `tempoGrid` | Kernel `TempoGrid` of the playing content on the clock's seconds axis: the applied document's `beatGrid`, else the selected clip's `BeatGrid` (its tempo, anchored at its first downbeat or beat); `undefined` without one. |
| `tempoClock` | Kernel [`TempoClock`](/kernel/api/#tempo-grids-and-the-tempo-clock) pairing `clock` with `tempoGrid`, for beats, bars and the next beat's reference time; `undefined` without either. A new object per read; it never re-anchors the clock. |
| `analyser` | Stable owned clip-output analyser or a borrowed backend's optional analyser. Empty input does not create a graph. |

### Events and lifecycle

`on`, `once` and `off` use `AudioPlayerEvents`; `on`/`once` return an unsubscribe.
`sourcechange` carries the discriminated `.source` snapshot, including same-transport document revisions.
`documentstatechange` carries `.documentBinding`; `statechange` carries `{playing}`, and
`timeupdate` carries `{seconds, duration, progress}`. Notifications are synchronous;
`loadstatechange` carries `{loading, error}` when the borrowed input's readiness
changes, including detachment and disposal. Backend subscriptions supply these
changes even while playback is paused; no polling or extra clock is required.
read current state again after reentrant callbacks. Source observation does not
start playback. `load` carries `{duration}`; `end` carries the clip or undefined
for a backend without one. `regionenter`, `regionleave` and `beat` forward clip
annotations. `error` carries an Error from the selected backend.

`dispose()` is terminal and idempotent. It releases subscriptions, observation,
owned clip/sequence engines, output, asset leases and only an internally created context. A supplied context
and borrowed transport remain caller-owned. Dispose owners separately in their
application lifetime. Cleanup must not reclaim a source selected by a callback.
Retired lease cleanup failures emit `error` without changing an adopted revision
to failed. Terminal cleanup continues through a throwing asset release, then
reports the first cleanup error to the caller.

`AudioPlayerTransport` requires seconds/duration/playing, play/pause/stop/seek.
Optional loading/loadError, clip/currentClip, analyser, clock, rate/volume/pan/pitch configuration,
preload/scratch and subscribe/onLoad/onEnd/onError ports expose backend
capabilities without DOM; clip loops are not part of it. An `AudioPlaylist`
implements this contract; use `AudioMixer.transport` for a mix. Backends with
readiness ports notify their `subscribe` observers whenever that state changes.
Loading describes the selected input, not unrelated prefetch.
An external backend may also declare `timingCapabilities`, `schedulingMode` and `followsSession`,
and implement `activateScheduling(): Promise<void>` and
`attachScheduling(binding): ConnectionLease`; these methods carry the same
ownership and timing contract as the owned buffer clip.
