`AudioClipPlayer` plays one `AudioClip`. It picks an engine, owns the audio
graph between the source and the destination, and emits the events a transport
UI needs — `timeupdate` while playing, `end` at the finish, `regionenter` and
`regionleave` as the playhead crosses the clip's own annotations.

The input clip is bound at construction and exposed as the readonly `clip`
property. Reading it allocates no playback resources; followers borrow this same
immutable data alongside the player's position. There is no clip-replacement
command, so a new clip means a new player. That is why [`AudioPlaylist`](/audio/headless/play/audio-playlist/)
builds one player per entry rather than swapping a clip into a shared one.

It **owns** the `AudioContext` only when it created one. Pass `audioContext`
and the player borrows it — `dispose()` then tears down its own graph and
leaves the context open. Applications can share a context deliberately without
assuming a fixed browser-wide context limit.

## Import

```ts
import {AudioClipPlayer} from '@webmusic/audio/play/headless';

const player = new AudioClipPlayer(clip, {volume: 0.8});
await player.play();
player.seek(12.5);
// Retain the player until the owning session/view is removed.
const dispose = () => player.dispose();
```

## Two engines, one contract

`engine: 'auto'` selects BufferEngine for decoded clips up to ten minutes.
Otherwise it selects MediaEngine when a source URL is available, and falls back to
BufferEngine without one. Force an engine with `engine: 'buffer'` or `'media'`.
Only the buffer path honors absolute future starts; media playback delegates
buffering and memory policy to its host adapter rather than promising flat memory.

`preservesPitch` is a media-engine property. The buffer engine changes pitch
whenever it changes speed, because that is what varying a buffer's playback
rate does; the option is a documented no-op there rather than a silent one.

## Ownership and the tap

`analyser` exposes an `AnalyserNode` in the player's own graph. Meters and
realtime analyzers **borrow** it: a borrower must not disconnect or
reconfigure it, since every other reader of the same tap would see the change.
`clock` is present only once the buffer engine has built its transport clock,
which can happen during `play()`, `preload()` or access to `analyser`. The bridge
reads it live rather than snapshotting it. Reading `analyser` materializes the graph
and throws after disposal; it is not a resource-free inspection.

## Scratch sessions

`beginScratch()` optionally borrows a scratch session over the player's decoded
PCM. It captures the current playing/paused state and suspends ordinary playback.
It returns `undefined` without changing playback for a disposed player, a zero-duration clip or unavailable decoded samples. Callers must check that result; a legacy structural player may not
provide the method at all. A nonempty decoded clip supports this independently
of its normal buffer/media engine selection; media still needs its existing
`mediaAdapterFactory`.

An `AudioScratchSession` (type exported from `/play/headless` and `/play`) exposes:

| Member | Contract |
| --- | --- |
| `active` | Whether this session owns scratching, including release inertia. It stays active during the coast; a superseded, canceled or completed session is inactive. |
| `moveToSeconds(seconds, audible = true)` | Move to a finite absolute clip-second position, clamped/wrapped by the active engine. Successive signed position changes determine scratch direction/speed through the player's existing volume, pan and effect route. `false` moves silently. Calling this during a coast settles that completion and retakes the same session. |
| `end(resume = true)` | `Promise<void>`; normal end coasts from the signed release speed toward the configured playback rate if previously playing, or zero if previously paused, then restores that state. It resolves after completion or cancellation, and rejects on coast/restoration failure. `false` cancels immediately without resume. |

The caller owns ending the session. Repeated `end(true)` during a coast awaits
its existing completion without restarting it; ending a stale/completed session
is a no-op. Retain the handle until completion so `end(false)` can still cancel.
The player owns its AudioContext, playback engine and shared route; ending a
gesture never disposes the player. External `play`, `pause`, `stop`, `seek`
(including `seekFraction` and legacy `scrub`) and disposal invalidate the session
and settle its pending coast. A newer session replaces it and inherits the
original playing intent, including when re-grabbing during release inertia.
Late readiness/end cannot resume obsolete work.

The current release transition lasts about **280 ms on the AudioContext clock**.
Both accepted position and scratch sound follow that signed velocity transition;
a previously paused source decelerates to rest, while a playing source converges
to its configured forward rate before ordinary playback resumes. A silent click
or release after motion has stopped restores directly, without a stale fling.
Context suspension cancels a pending coast. Volume/pan changes retain the session.
Rate/loop changes retain a held gesture, but finish an active coast at its current
accepted position and restore the prior state with the new configuration.

The backend retains native playback phase through bounded local PCM windows,
with smooth rate changes and short crossfades for direction changes, refills or
large position corrections. Pointer updates do not restart a separate audio grain.
Signed scratch speed is capped at 8 times sample speed; the audio-clock watchdog
brakes and silences stationary input. Reverse windows copy only local PCM and
never modify the original clip. Speed also changes pitch; this is not
pitch-preserving time stretching. Cancellation, external transport commands and
disposal stop scratch output immediately. With a range loop, pre-loop lead-in
remains available and windows respect the active loop edges; seamless scratch
loop wrapping is not promised. The existing `scrub(deltaSeconds)` is a separate
relative-seek convenience and does not start an audible scratch session.
[`<audio-view drag-mode="scrub">`](/audio/element/view/audio-view/#dragging-and-seeking)
composes this capability with centered geometry and pointer lifecycle.

## Time, ownership and contract source

An independent player owns playback state on the clip-seconds axis. Its context is the audio
reference; it is not automatically the authority for every player on the page.
Views follow its notifications or reader. Under native looping, `seconds` wraps
while `clock.positionAt(t)` remains unwrapped. A seek before a buffer's scheduled
start retains that absolute start time and relocates the held position.

A `load` listener can pause or stop the pending start. Seeking from that listener
changes the start position without cancelling the play intent. Region events use
the engine's actual clamped/wrapped position. A transport command from a
`timeupdate`, region or beat listener invalidates the remaining notifications
from the interrupted observation batch; committed region membership prevents
seeking within the same region from recursively entering it again.

Range-loop options must have finite bounds and a positive span after clamping a
negative start to zero. Invalid ranges throw `RangeError`; rejected live edits
preserve the accepted loop. Buffer ranges must overlap the known clip duration.
For media, later metadata can leave no playable span: the watcher stops and the
stream finishes normally. See [engine range rules](/audio/headless/play/engines/).

The public barrel and `packages/audio/src/play/headless/player.ts` define the value, option, state and event
contracts described below. The reference does not turn private implementation
fields into public API.

## Shared Session scheduling

Buffer playback can borrow a read-only
[Session scheduling binding](/kernel/api/#session--webmusickernelsession).
Register `prepare: () => player.preload()`,
`activate: () => player.activateScheduling()` and
`attachScheduling: binding => player.attachScheduling(binding)` on the Session
participant. Preparation constructs decoded resources without resuming a suspended
context. Activation resumes that context before the Session chooses its future
origin. All participants must use that same AudioContext time reference; affine
participant offsets and scales map Session seconds to clip seconds.

While attached, `clock` reads the mapped, unwrapped Session clock. `seconds` folds
the Session loop and clamps to the playable clip; it can remain at an endpoint
during scheduled silence. Direct play, pause, stop, seek, rate and loop commands
throw because the Session owns those changes. `beginScratch()` returns undefined.
Use Session commands; gain, pan and effects remain local controls.

`schedulingMode` distinguishes the actual backend:

| Mode | Timing behavior |
| --- | --- |
| `independent` | Ordinary player-owned transport. |
| `session-native` | Buffer sources start at the shared absolute origin. A mapped loop wholly inside the clip uses one continuous native looping source, including non-unit rates. |
| `session-lookahead` | Negative mapped positions or loops extending outside the clip use bounded sources and silence for the non-playable span. A 25 ms worker-backed tick fills a 200 ms scheduling horizon; already scheduled starts use the audio clock, but a long scheduling stall can miss a future pass. |
| `approximate-media` | HTML media playback has no native future-start primitive or shared sample clock. Use the Session's legacy transport participant coordination; `attachScheduling` rejects this backend. |

Seek, pause, rate and loop changes invalidate queued sources before the Session
commits a new anchor. A frozen AudioContext clock does not advance scheduling.
Releasing the returned lease cancels only this player's sources and subscriptions;
the borrowed Session remains unchanged and the player retains a paused local
position and its effective mapped rate for subsequent independent playback.
Disposal also releases that lease and never closes a borrowed context.
Already sounding insert tails follow the effect's own decay; source cancellation
does not forcibly erase a reverb or delay buffer. Timing describes graph scheduling,
not hardware output latency, and rate changes do not preserve buffer pitch.

## Realized effects and module output

`setEffect(recipe)` updates the legacy compatibility slot of the prepared
`insertChain`; explicit insert slots remain in place. `outputPort` exposes the
prepared stable output for leased replacement, sends and taps. These are lazy
resources: observing module capabilities does not prepare a graph.

The `AudioPlayer` facade exposes `.module` for capability discovery. Its
`insertChain` is available for its owned clip engine; a source-free or borrowed
backend does not invent a chain. Explicit preparation and ownership follow the
selected backend. Use [Kernel routing leases](/kernel/api/#module--webmusickernelmodule)
when admitting an output to a mixer or adding a side tap.
