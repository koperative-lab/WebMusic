`@webmusic/bridge` is a **single-entry package**: the root is the whole API.
It is the only package allowed to import both families, and both are peer
dependencies alongside `@webmusic/kernel`. Bridge can coordinate supplied
players or construct explicitly owned instances through its factories.

It does not decode audio, parse notation, or draw anything. Those live in
[`@webmusic/audio`](/audio/api/) and [`@webmusic/score`](/score/api/); what is
here is only the work that needs *both*.

## Install

`npm install @webmusic/bridge` — use an available published version or the local workspace. It has no optional peers of its own; it inherits whatever the two families need.

## Entry map

| Subpath | Form | What is there |
| --- | --- | --- |
| `@webmusic/bridge` | root · the whole API | Everything below. |
| — | [Headless](/bridge/headless/) | `createScoreAudioSession` and `registerAudioParticipant` are root exports, documented under the headless contract because the composition is constructed and disposed rather than called. |

There is no `/headless` subpath, no `/element`, and no `/auto`: the bridge
ships no Web Components. It gets none until it has one to ship.

## Session composition

The stateful half of the package. `createScoreAudioSession` puts a Score engine
and an Audio clip player under one Session — the single command authority of
modular composition (DEC-068) — each mapped onto its own axis
(`score-nominal-seconds`, `clip-seconds`). `registerAudioParticipant` is the
adapter it uses to register any Headless Audio engine on the shared
`clip-seconds` axis. Both are documented on
[their page](/bridge/headless/score-audio-session/). The former
`ScoreAudioSync` master/follower family and its factories and adapters are
removed in 0.3.0.

## Modules and data functions

`createScoreAudioSession` and the project plugins create modules. The timeline
conversions, `renderScoreToClip` and `scoreFromTranscription` are data
functions: their results feed modules (a rendered clip becomes an
`<audio-player>` source; a transcribed `Score` becomes a `<score-player>` source).

## Timeline conversions

The two families deliberately keep different musical time models — Score's
exact `TimeMap` (rational quarters → seconds) and Audio's `BeatGrid`
(beats[] in seconds). Both project onto the same seconds ruler, so they
convert:

```ts
import {beatGridFromTimeMap, timeMapFromBeatGrid} from '@webmusic/bridge';

// Exact at the sampled positions; intervening tempo changes can be lost.
const grid = beatGridFromTimeMap(score.timeMap, {durationQuarters: 64});

// Approximate: each inter-beat interval becomes one tempo segment.
const map = timeMapFromBeatGrid(gridFromTempoDetection);
```

Use `beatGridFromTimeMap` to hand a score's tempo curve to audio-side tools
(beat-synced effects, waveform beat markers); use `timeMapFromBeatGrid` to
carry a detected tempo grid (e.g. from `@webmusic/audio/analyze`'s tempo detection)
into score-side quantization. `DEFAULT_MAX_MAPPED_BEATS` is the ceiling that
keeps a pathological tempo map from generating an unbounded grid.

`timeMapFromBeatGrid` maps each grid beat to one quarter note, sets quarter
zero to second zero, and supplies a default 4/4 meter. Retain the original
`grid.beats[0]` offset separately when aligning a recording. It does not recover
the original meter or the subdivision factor used to create a grid. These
functions therefore do not form a lossless round trip.

### Mapping contract

| Member | Default | Contract |
| --- | --- | --- |
| `beatGridFromTimeMap(map, options): BeatGrid` | — | Samples a Score `TimeMap` at uniform quarter subdivisions, returning Audio beat positions in seconds. The final sample rounds up to the next subdivision if needed. |
| `options.durationQuarters` | Required | Finite number greater than zero; requested span on the quarter axis. |
| `options.beatsPerQuarter` | `1` | Positive safe integer; samples per quarter. The resulting grid's beat index is a subdivision index. |
| `options.maxBeats` | `DEFAULT_MAX_MAPPED_BEATS` (`1_000_000`) | Safe integer at least 2. The allocation includes the zero-position sample; excessive spans throw `RangeError`. |
| `timeMapFromBeatGrid(grid): TimeMap` | — | Each positive inter-beat interval becomes a tempo segment; zero/nonpositive intervals throw `RangeError`. With fewer than two beats, uses `grid.bpm`. |

`BeatGridFromTimeMapOptions` is the options shape above. Both operations return
data, own no running transport or audio resources, and need no disposal.

## Offline rendering

`renderScoreToClip(score, options?)` plays a score into an `OfflineAudioContext`
and returns the result as an `AudioClip` — a matched backing track, without a
speaker or a user gesture. This is what lets the composition demo make the clip
the sounding source while a muted Score engine drives the visuals.

The renderer includes an effect/release tail by default; render with
`tailSeconds: 0` when the clip must end with the score. A `tempo` override that
differs from the Score's base tempo changes the clip's time axis: set
`clipPositionScale` on `createScoreAudioSession` accordingly, or render at the
base tempo and change speed with the Session's `setRate()`.

For repeated notation, call `expandRepeats(score)` first, then render and pair
the expanded Score instance. Passing `scoreOptions.expandRepeats` with a
Bridge-rendered clip would expand only the live player, so the factories reject
it before allocating playback resources.

Its signature is `renderScoreToClip(score: Score, options?: RenderOptions):
Promise<AudioClip>`. Options and synth ownership follow
[Score's offline render helpers](/score/headless/play/score-player/).
An `OfflineAudioContext` implementation and an offline-compatible synth are
required; self-routing Tone/Spessa synths do not route into that capture graph.
Rendering rejects on preparation/render failures. The returned clip is data,
with the renderer's sample rate and channel count, and has no playback lifetime
until supplied to a player. Timbre, effects, tempo, and rendering tails are
choices made during rendering, not information recoverable from the clip's
original notation.

## Audio → Score assembly

`@webmusic/audio/analyze/transcribe` emits family-neutral note events; the bridge
turns them into a real `Score`:

```ts
import {transcribe} from '@webmusic/audio/analyze/transcribe';
import {scoreFromTranscription} from '@webmusic/bridge';

const {notes, bpm} = await transcribe(clip, {quantize: true});
const score = scoreFromTranscription(notes, {bpm, quantizeGrid: 4});
```

Notation snaps to the grid (default sixteenths; `quantizeGrid: 0` still rounds
to a 1/480-quarter tick). Accepted notes retain their supplied onset and
duration in `performed.onsetSec` / `durationSec`; velocity is converted to
integer MIDI units. Pitches are rounded and out-of-range results are dropped.
This preserves supplied timing alongside notation but cannot recover material
the transcriber did not represent. Note that
`transcribe` itself needs its optional peers installed
(`@spotify/basic-pitch`, `@tensorflow/tfjs`); `scoreFromTranscription` is
pure and always available. `DEFAULT_MAX_TRANSCRIPTION_MEASURES` and
`DEFAULT_MAX_TRANSCRIPTION_NOTES` bound what one call will assemble.

### Assembly contract

`scoreFromTranscription(notes: readonly TranscribedNote[], options?:
ScoreFromTranscriptionOptions): Score` is synchronous. It creates one part,
one voice, a constant tempo, and enough measures to cover the accepted notes
(at least one measure for empty input). It does not detect instruments,
voices, meter, or a variable tempo map.

| Option | Default | Contract |
| --- | --- | --- |
| `bpm` | `120` | Finite, positive output tempo. Pass the desired interpretation explicitly. |
| `timeSignature` | `{numerator: 4, denominator: 4}` | Positive safe-integer numerator and denominator; defines measure duration. |
| `quantizeGrid` | `4` | Nonnegative safe integer subdivisions per quarter. Zero uses 480 ticks per quarter; rounded durations have at least one grid unit. |
| `title` | `'Transcription'` | Score title. |
| `partName` | `'Transcribed'` | The single part's name. |
| `maxNotes` | `DEFAULT_MAX_TRANSCRIPTION_NOTES` (`100_000`) | Positive safe integer limiting input count, before pitch filtering. |
| `maxMeasures` | `DEFAULT_MAX_TRANSCRIPTION_MEASURES` (`4_096`) | Positive safe integer limiting materialized measures. |

For each input note, `midi` must be finite; its rounded pitch outside 0–127
is skipped. For an accepted pitch, seconds must be finite, nonnegative, and
ordered, and velocity must be finite. Velocity is multiplied by 127, rounded,
and clamped to 1–127. Invalid options, accepted-note values, unsafe timing
arithmetic, or resource-limit violations throw `RangeError`. Assembly owns
no context, subscription, or running clock and has no disposal step.

## Project module factories

`createWebMusicProjectPlugins(): readonly ProjectPluginFactory[]` returns trusted
factory definitions for [Kernel projects](/kernel/api/#versioned-projects).
Register them in `ProjectPluginRegistry` explicitly. Calling this function
creates no graph, loads no asset and registers nothing globally. Each factory
creates a fresh instance owned by `ModuleProjectRuntime`; all use the project's
borrowed audio environment and staged output destination.

Every built-in factory uses exact plugin version **`1.0.0`**. This is the
project-plugin schema version, separate from the package release version.

| Plugin ID | Configuration and assets | Ports / parameters |
| --- | --- | --- |
| `webmusic.score-player` | Asset role `source` must resolve to a Score. `waveform` defaults `sine`; accepts sine/square/triangle/sawtooth. `offsetSeconds` defaults 0 and `positionScale` 1. Owns an oscillator Sound and one ScorePlayerModule. | Audio `output`; oscillator/shared ADSR parameters, including gain, detune, cutoff, resonance and busGain. |
| `webmusic.audio-player` | Asset role `source` must resolve to an AudioClip. `offsetSeconds` defaults 0 and `positionScale` 1. Owns one AudioClipPlayer. | Audio `output`; synchronous `volume` (0…1) and `pan` (−1…1). Native automation uses an audio bus/effect parameter. |
| `webmusic.score-rack` | `masterVolume` defaults 1. Optional `channels` maps stable child module IDs to `{volume?, muted?, solo?}`; channel volume is 0…1. Settings apply after child admission and live states are exported while unresolved records are retained. | Audio `input` and `output`; a child context owned by this module admits outputs as real Rack channels. |
| `webmusic.audio-bus` | `gain` defaults 1. A child context owned by this module routes its normal outputs into this bus. | Audio `input`, `output`; native gain parameter. |
| `webmusic.effect` | Required `type`: gain, filter, delay, compressor or reverb. `options` defaults `{}` and uses the effect's named numeric options. Filter options additionally accept a Biquad `type` (default lowpass). | Audio `input`, `output`; the realized effect's shared parameters. |
| `webmusic.lfo` | Session-relative `frequency` defaults 1 cycle/Session-second, `phase` 0 cycles, `waveform` sine and `loop` repeat (or once). | Control `output`; shared frequency/phase handles. Paused Session produces zero; phase reconstructs from Session position. |

Gain options are `gain`; filter options are `frequency`, `Q`, `gain`, `type`;
delay options are `delaySeconds`, `feedback`, `wet`, `dry`; compressor options
are `threshold`, `knee`, `ratio`, `attack`, `release`; reverb options are
`seconds`, `decay`, `wet`, `dry`. Units and backend ranges follow
[Score Effect](/score/headless/play/effect/). Runtime module `params` restore
onto realized handles after construction, independently of recipe defaults.

The application supplies `resolveAsset(reference, signal)`. Bridge checks the
resolved domain object; it does not fetch URLs, decode arbitrary files, persist
sample data or install missing code. A saved plugin reference without a matching
registry entry remains unresolved until an explicit registration and retry.
See [the complete project example](/bridge/modular-composition/#save-and-edit-a-project).

## API Reference

Every export of the root, exactly once.

| Export | Kind | Use it for |
| --- | --- | --- |
| `createScoreAudioSession` | factory | [createScoreAudioSession](/bridge/headless/score-audio-session/) — one Session over a Score engine and an Audio clip. |
| `registerAudioParticipant` | adapter | Register a Headless Audio engine with a Session on `clip-seconds`. |
| `beatGridFromTimeMap` | function | Sample a score's exact tempo map onto an audio `BeatGrid`. |
| `timeMapFromBeatGrid` | function | Carry a detected beat grid into a score `TimeMap`. |
| `renderScoreToClip` | function | Render a score offline into an `AudioClip`. |
| `scoreFromTranscription` | function | Assemble transcribed note events into a `Score`. |
| `createWebMusicProjectPlugins` | factory | Exact-version Score, Audio, Rack, bus, effect and Session-LFO factories for Kernel project restore. |
| `DEFAULT_MAX_MAPPED_BEATS` | constant | The beat ceiling `beatGridFromTimeMap` will not exceed. |
| `DEFAULT_MAX_TRANSCRIPTION_MEASURES` | constant | Measure ceiling for one assembly. |
| `DEFAULT_MAX_TRANSCRIPTION_NOTES` | constant | Note ceiling for one assembly. |
| `CreateScoreAudioSessionOptions` · `ScoreAudioSession` | types | Options and result of `createScoreAudioSession`. |
| `AudioParticipantOptions` · `AudioParticipantPlayer` | types | Options and engine surface of `registerAudioParticipant`. |
| `BeatGridFromTimeMapOptions` | type | Options for `beatGridFromTimeMap`. |
| `ScoreFromTranscriptionOptions` | type | Options for `scoreFromTranscription`. |
